## H. 适合大学生团队、有限时间内的 MVP

### H.1 硬约束与目标

| 项 | 设定 |
|---|---|
| 团队 | 🔴 **最多 3 人**——**本校通知硬约束**：团队人数 ≤ 3 人（鼓励跨专业、跨年级组队，可个人参赛）。**全部排期与分工已按 3 人重做**，见 H.5 |
| 周期 | **6 周**（每周约 12~15 小时/人） |
| 学科 | **只做初中数学一个学科**（迷思概念最清晰、评分最客观、你校数学师范生基数大） |
| 交互 | **纯文本对话**（不做语音、不做数字人） |
| 虚拟学生 | **3 个**（迷思型、沉默型、过度积极型） |
| 轮次 | **两轮试讲**（同一份教案），这是闭环的最小证明 |

### H.2 六周排期（每周一个可验证的产出）

| 周 | 目标 | 该周结束必须能演示的东西 |
|---|---|---|
| W1 | 打通数据流骨架 | 上传一份 PDF 教案 → 屏幕出现结构化"教学目标/重难点/迷思概念"卡片（A1 跑通） |
| W2 | 虚拟学生成型 | 生成 3 个学生卡片，每个能看到画像 + 预设迷思概念；能跟单个学生来回聊 5 轮（A2+A4 跑通） |
| W3 | 多学生课堂 + 导演 | 3 个学生按 Director 调度轮流发言，**不重复、不抢话**；能触发"走神"事件（D0+A3 跑通） |
| W4 | 行为编码 + 指标 | 试讲结束后出现 FIAS 标签序列 + TT/ST/IDR/SIR 四个数字（A5 跑通，指标由代码算） |
| W5 | 评价 + 反思 + 教案修订 | 评价报告（雷达图 + 证据高亮）+ 3 个反思追问 + 教案 patch 清单（A6+A7+A8 跑通） |
| W6 | 闭环 + 打磨 | 第二轮试讲 + **前后对比页**；6 分钟演示跑 10 遍不出错；录制备份视频 |

> **每周必须"能演示"**，否则这一周等于没做。这条纪律是学生项目不烂尾的关键。

### H.3 技术选型（按"学生团队最省事"原则，附理由）

| 层 | 选择 | 为什么（对比后选它） |
|---|---|---|
| 前端 | **Next.js 15 + TypeScript + Tailwind + shadcn/ui** | 与 OpenMAIC 同栈（可参考其组件组织）；生态成熟；雷达图/热力图用 ECharts 或 Recharts |
| 后端 | **FastAPI（Python）** | Agent 编排生态在 Python（LangGraph）；教育数据处理（pypdf、python-docx）也在 Python；**不要用 Next 的 API routes 写 Agent，会让前后端同构变得痛苦** |
| 编排 | **LangGraph** | 状态机 + 可中断 + 可恢复，正好对应"备课→试讲→编码→评价→反思→修订"的阶段流转；OpenMAIC 同栈 |
| 数据库 | **SQLite → 需要时换 Postgres** | 比赛规模 SQLite 足够；**别一开始上 MongoDB+RabbitMQ**（MAIC-Core 那套 7 个常驻 worker 对我们是过度设计） |
| ORM/迁移 | SQLModel 或 SQLAlchemy + Alembic | 参考 edu-agent 的做法，数据表要能演进 |
| 模型 | **国产 API 分阶段路由**：便宜快模型跑虚拟学生（如 DeepSeek / Qwen-flash 级）；强模型跑评价与教案修订 | 成本可控 + 学生发言要快；**注意**：OpenMAIC 有"分阶段模型路由"的现成设计可参考 |
| 检索 | **先做词法检索（BM25/关键词），不上向量库** | 单份教案的上下文完全可以整篇塞进去；OpenMAIC 的 RAG 默认就是**内存词法索引**，不是向量库——**人家上万 star 的项目都没上向量库，我们更不用** |
| 流式 | SSE | 与 OpenMAIC 一致；学生发言必须逐字蹦出来才有"活人感" |
| 部署 | 本机 + 一个公网可访问的临时部署（比赛要求"可公开访问地址"） | 见 M 节的材料清单要求 |

### H.4 MVP 验收标准（可测，写进说明书）

> 全部为**可当场验证**的硬标准，不含"体验良好"之类的软话。

1. 上传一份初中数学 PDF 教案，**60 秒内**生成结构化解析（含 ≥3 条迷思概念假设）。
2. 生成 **3 个**虚拟学生，每人有：画像、预设迷思概念、参与度基线、语言约束。
3. 试讲 **10 轮对话内**，必须出现：**至少 1 次答错、1 次质疑或超纲提问、1 次走神/沉默**。
4. **状态一致性测试**：学生 S1 在第 3 轮答错后，第 8 轮仍表现为"未理解"（**不得自行变聪明**）。
5. 试讲结束输出 FIAS 编码序列（每句一个标签）+ 4 个指标（TT/ST/IDR/SIR），**指标由代码计算**（同一份对话重复计算必须完全一致）。
6. 评价报告中**每条结论均带 `evidence_turn_ids`**，点击可高亮原文；**空话（无证据结论）数量必须为 0**。
7. 给出 3 个反思追问，且**不出现 AI 代写的反思文本**。
8. 给出教案修订 patch 清单，每条含 `reason`；结构校验通过率 100%（引用不存在的 objective_id 视为失败）。
9. 第二轮试讲后，**前后对比页**能显示 IDR、等待时间、叫答分布的数值变化。
10. **离线/断网可演示**：准备一套预跑数据 + 录屏备份（见 K.6）。

### H.5 3 人分工（**本校通知硬约束：团队 ≤3 人**）

> ⚠️ **这条是硬约束，不是建议**：通知原文"团队人数≤3人，鼓励跨专业、跨年级组队"。下面按 3 人重排。

| 角色 | 负责 | 交付物 |
|---|---|---|
| **P1 · 引擎** | D0/A1/A2/A3/A4（导演 + 教案分析 + 铸造工坊 + 场景导演 + 虚拟学生运行时）、LangGraph 图、提示词工程、认知状态机、JSON Schema 校验与重试 | **试讲引擎**（本项目最重的一块） |
| **P2 · 数据与评价** | A5/A6（FIAS 编码 + 评价）、**指标计算代码（纯 Python，可先写先测）**、证据锚点、数据库与事件流、两轮对比计算、编码一致性比对工具 | **评价引擎 + 数据层** |
| **P3 · 前端与交付** | 全部页面、试讲教室交互、报告可视化（雷达图 / FIAS 热力图 / 对齐矩阵 / diff / 成长曲线）、**展示视频 + PPT + 答辩演练** | **界面 + 比赛材料** |
| **三人共同承担** | 教案定稿、"负负得正"迷思概念与台词库、用户测试执行、说明书统稿 | 知识资产 + 测试数据 + 说明书 |

**必须点名的两个现实问题**：

1. **3 人做原来 4 人的范围，做不完。** 所以下一步不是"加油"，而是**砍范围**——见下方削减清单。
2. **"内容与测试"这块最容易没人认领。** 原本这是一个专职角色（D），现在被摊到三个人身上，**结果往往是三个人都在写代码、没人做测试**。**建议明确指定一人为"测试与材料负责人"（通常是队长或表达最好的那位），并把他的代码任务减到最少。**

**3 人版的 MVP 削减清单（按"砍掉损失最小"排序）**

| 砍什么 | 怎么砍 | 损失 |
|---|---|---|
| ① 关键事件注入 | 从"多类事件 + 智能时机"降级为 **2 个手动按钮**（走神、沉默） | 小——Demo 记忆点保留 |
| ② 教案 patch 自动落版 | 只输出**建议清单 + 理由**，不自动生成 v2 diff | 小——闭环仍成立（人手动改） |
| ③ 虚拟学生数量 | 从 4~5 个降到 **3 个**（迷思型 + 沉默型 + 过度积极型） | 小——覆盖了核心原型 |
| ④ 反思教练独立 Agent | 不做独立 Agent，**用一段固定追问模板 + 关键片段回填** | 小——理念（不代写）仍保留 |
| ⑤ 成长档案（多次训练曲线） | 只做**两轮对比**，不做跨会话历史曲线 | 中——但"两轮"已足够证明闭环 |
| ⑥ 学科教研员 Agent | **明确放二期**（原计划就是二期） | 无 |
| ⑦ 学生语言画像精细调优 | 只用**句长上限 + 禁用词表**两条硬约束 | 中——真实感会打折，但可接受 |

> ❌ **绝不能砍的三样**：**FIAS 编码 + 代码算指标**、**两轮试讲对比**、**每条结论带原文证据**。
> 砍掉任何一个，项目就退化成普通聊天机器人。

### H.6 必须提前防的三个坑

| 坑 | 表现 | 对策 |
|---|---|---|
| **学生太配合**（"乖学生"） | 学生永远答对、永远认真听 | ① 状态机强制"答错后不解悟"；② 走神由代码触发而非 LLM 自觉；③ 提示词里写死"禁止替老师总结" |
| **Demo 现场翻车** | 网络抖动、API 限流、模型抽风 | ① 每个 Agent 输出都有 schema 校验 + 重试 + 降级；② **准备预跑数据可一键回放**；③ 录制备份视频；④ Demo 用固定教案（不现场随机） |
| **评价不可信** | 评委问"你凭什么说 IDR 0.12 就是不引导" | ① 指标公式全部写在说明书里；② 抽样 20 条做**人工标注一致性**（邀请指导老师）；③ 报告里标注"编码为 AI 辅助，最终解释权归指导教师" |

### I.2 核心数据表（MVP 最小集）

```sql
lesson(id, subject, grade, duration_min, raw_file_path, created_at)
lesson_version(id, lesson_id, version_no, structure_json, parent_version_id, created_at)
   -- structure_json = A1 的严格 JSON；v2 由 patch 应用生成
session(id, lesson_version_id, user_id, round_no, status, started_at, ended_at)
turn(id, session_id, idx, speaker_type[teacher|student], speaker_id,
     text, fias_category, behavior, t_offset_ms, wait_time_ms)   -- ★ 事件流，append-only
event(id, session_id, turn_id, type[distraction|silence|challenge|overflow],
      payload_json, injected_by[code|llm])
metric(id, session_id, tt, st, idr, sir, bloom_json, wait_avg_ms,
       call_distribution_json, computed_at)                     -- ★ 由代码从 turn 重算
report(id, session_id, scores_json, strengths_json, improvements_json,
       alignment_matrix_json, risk_flags_json, model, created_at)
reflection(id, session_id, prompts_json, user_text, created_at) -- ★ user_text 由人写
patch(id, session_id, lesson_version_id, op, path, value_json, reason, evidence_json, accepted)
student_profile(id, session_id, archetype, persona_json, misconception_id, state_json)
```

> **"双写 + 可重算"是这个架构最重要的设计**：它让"AI 评价"具备了**可审计性**——评委问"这个分数怎么来的"，我们能从事件流一步步重算给他看。**这是把 AI 评价从"黑箱"变成"透明"的关键，也是"合规与伦理"拿分的核心。**

### I.3 七条工程铁律（都是本次调研带回来的教训）

1. **LLM 只做分类，指标由代码算**（编码可信度）。
2. **LLM 只选人，代码兜底**（MAIC-Core 的 Director 教训）。
3. **每个 LLM 输出都要有 JSON schema 校验 + 重试 + 降级**（OpenMAIC 的 Evaluator：解析失败时叙事仍展示、结构化数据不落库）。
4. **注入"本轮同伴已发言"上下文**，否则多学生会重复说同样的话（OpenMAIC `peer-context.ts`）。
5. **教案修订用校验式 JSON Patch，不重新生成教案**（OpenMAIC v0.3.1 的做法）。
6. **一次请求只跑一轮 director→agent**，多轮由前端序列化驱动——**避免多 Agent 无限对话**（OpenMAIC 的 "no maxTurns cap — the topology is the bound"）。
7. **为"翻车模式"写测试集**：学生太配合、学生自相矛盾、Director 连续选同一人、评价输出空话、patch 引用不存在的目标——**每个都要有一个断言**（借 OpenMAIC `eval/orchestration/scenarios/` 的思路）。

### I.4 与三个参考项目的对应关系（答辩时的"技术血统"）

| 我们借鉴了什么 | 来自 |

## J. 前端页面结构

**9 个路由，按"师范生的真实操作顺序"排列**（这也是 Demo 的导航顺序）。

| 路由 | 页面 | 关键元素（评委能看见的东西） |
|---|---|---|
| `/` | **首页 / 我的训练** | 一句话价值主张；"开始一次试讲"主按钮；历史训练卡片（显示最近一次 IDR 变化箭头） |
| `/prepare` | **备课台** | 拖拽上传区；学科/学段/课时选择；右侧实时出现 AI 解析结果卡片：**教学目标（ABCD 四要素可展开）/ 重难点 / 学情假设 / 迷思概念**；底部**"设计薄弱点"红框**（如"O2 没有对应评价"）；每个字段**可人工编辑**（人在环） |
| `/cast` | **学生编排** | 3~4 张学生卡（头像用色块 + 名字 + 原型标签）；每张卡显示：画像、**预设迷思概念**、参与度滑条、语言约束标签；"换一个""调难度"按钮；**"这个学生会在第 3 轮坚持错误"的预告文案**（这是创新点的可视化） |
| `/classroom` | **试讲教室**（核心页） | 左侧：学生座位区（发言者高亮、**被忽略学生显示灰化计时器**）；中间：对话流（学生气泡带"行为标签"如「走神」「质疑」）；右侧：**实时 FIAS 标签瀑布**（每句一个色块，1-4 蓝=间接影响，5-7 红=直接影响）+ 计时器 + 课堂进度；底部：老师输入框 + "结束试讲"；**关键事件以横幅提示出现**（"小周已走神 2 分钟"） |
| `/report` | **评价报告** | 顶部：六维雷达图 + 总分；中部：**四个指标大卡片**（IDR 带"专家人类教师 1.473"的对照刻度，视觉冲击极强）；**FIAS 9×9 迁移矩阵热力图**；**提问层次分布**（布鲁姆六层柱状）；**叫答公平性**（每个学生被叫次数条形图 + 被忽略学生红色标注）；底部：**证据链接列表**（每条结论可点击 → 跳到 `/classroom` 高亮原文） |
| `/alignment` | **一致性对齐矩阵** | 四列矩阵（目标 / 教案活动 / 实际发生 / 评价手段）+ 四色诊断（对齐 / 目标落空 / 游离活动 / 不可评目标）；**这一页是"教育专业性"的门面** |
| `/reflect` | **反思工作台** | AI 的 3~5 个追问逐条出现；**只有输入框，没有"AI 帮我写"按钮**（刻意的，演示时要点出来）；底部"提交我的反思" |
| `/revise` | **教案修订** | 左 v1 / 右 v2 并排 diff（**修订处高亮**）；下方每条 patch 卡片：`理由 + 证据 + [接受] [拒绝]`；"导出为 Word"（对应比赛材料） |
| `/growth` | **成长档案** | 多次试讲的折线图（IDR / 等待时间 / 叫答覆盖度）；"导出过程性证据包（PDF）"按钮——**对接教育实习/微格课程考核** |

**UI 设计纪律**：
- **不要做一个"聊天框"**——聊天框会让评委第一反应是"这不就是 ChatGPT"。**必须让"学生座位区 + 实时 FIAS 瀑布 + 被忽略计时器"始终在屏幕上**，这三个元素是"我不是 ChatGPT"的视觉证明。
- 颜色语义固定：**蓝=间接影响/引导，红=直接影响/讲授**。让评委不用解释就能看懂 IDR 的含义。

## K. 比赛现场 5 分钟 Demo 流程（分秒脚本）

> 设计原则：**前 25 秒定生死**（评委在这一分钟决定要不要认真听）；**每一段都要有一句"可被记住的话"**；**3:15 处必须出现"打脸时刻"**（数据证明师范生的问题），这是全场记忆点。

| 时间 | 画面 | 台词 / 动作 | 记忆点 |
|---|---|---|---|
| **0:00–0:25** | 首页 + 一张对比图 | "师范生上一次讲台之前，平均只有 **1~2 次**真实试讲机会。同学互评的标准答案是'**挺好的**'。" 停顿。 "而我们发现：**AI 很会讲课，但几乎不会引导**——它的间接影响比 IDR 只有 0.058，人类专家教师是 1.473。**所以别让 AI 当老师，让 AI 当那个最会添乱的学生。**" | 一句立论：**"让 AI 当学生"** |
| **0:25–1:00** | `/prepare` 备课台 | 现场拖入一份初中数学教案 PDF。60 秒内出现解析卡片：目标 / 重难点 / 学情假设 / **3 条迷思概念**。 指红框："它已经提前告诉你，**你的 O2 没有任何评价手段**。" | AI 不只是"读懂教案"，是"**指出教案的漏洞**" |
| **1:00–1:30** | `/cast` 学生编排 | 生成 3 个学生：**迷思型小林**（"会把负负得正当规则套用"）、**沉默型小周**（参与度 0.3）、**过度积极型阿豪**（爱抢答）。 指卡片："每个学生**带着错误来上课**。这是我们和其他虚拟学生的区别——**别人造乖学生，我们造反事实学生。**" | **"别人造乖学生，我们造反事实学生"** |
| **1:30–3:15** | `/classroom` 试讲教室 | 讲师**故意讲得快、只叫前排小林**：① 小林答错并**坚持**（"可是老师，负负就是得正啊"）；② 小周**走神**（横幅："小周已走神 2 分钟"）；③ 阿豪**抢答超纲**（"那如果是负数乘分数呢？"）。 讲师现场处理其中一个事件。 右侧 FIAS 瀑布**实时滚动**，同时弹出提示："**你已连续 3 次叫答同一位学生**"。 | **课堂是"活"的**：会出错、会走神、会挑刺 |
| **3:15–4:00** | `/report` 评价报告 | 🔥 **打脸时刻**：IDR = **0.12**（旁边标注"专家人类教师 1.473"）；"**你的 6 次提问里有 5 次是记忆型**"；**小周被忽略 11 分钟**（红色标注）。 点击一条结论 → **自动跳回原文高亮**那一句。 | **"这不是打分，是有证据的诊断"** |
| **4:00–4:30** | `/reflect` + `/revise` | 反思页出现 3 个追问，**只有输入框，没有"AI 帮我写"**： "你在第 3 分钟问'记住负负得正了吗'，小林点头了；但第 7 分钟她又做错了。**这说明什么？**" 切换到教案 v2 diff：新增"追问算理"环节，每条修订都写着理由。 | **"AI 拒绝替你想"**（教育理念亮点） |
| **4:30–5:00** | `/growth` + 收尾 | 第二轮试讲对比：**IDR 0.12 → 0.58**，等待时间 **1.1s → 3.4s**，被忽略学生 **1 → 0**。 收尾："我们把师范生的**试错成本降到零**。它不是要取代指导老师——研究证明人类导师的反馈更可信；**它是让老师见到学生之前，先在这里失败十次。**" | **闭环 + 克制的价值主张** |

### K.6 Demo 兜底（必须做）

1. **固定教案**：Demo 用同一份初中数学教案，**不要现场随机**。
2. **预跑数据**：全流程跑一遍并落库，准备"一键载入历史会话"入口（网络/模型异常时立即切）。
3. **录制备份视频**：完整 5 分钟录屏，U 盘 + 本地双备份。
4. **降级开关**：模型超时时，编码/评价走"规则+模板"降级路径（输出仍然完整，只是文采差一点）。
5. **提前试 3 次网络**：现场 WiFi、热点、手机热点各一次。

## L. 项目名称、宣传语与核心创新点

### L.1 名称候选（附取舍）

| 名称 | 含义 | 优点 | 风险 |
|---|---|---|---|
| **课镜**（推荐） | 课堂的镜子——照出你自己看不见的教学行为 | 好记、有教育意象、呼应"客观之镜"；与"AI 测评"有区分（镜子不评分，是让你看见） | 略偏"评价"，需在副标题补"陪练" |
| **同窗** | 你的第一批学生 | 意境好："每个师范生都该先有一个班" | "同窗"指同学，而我们的 AI 是学生，语义略绕 |
| **讲台前** | 上讲台之前 | 场景感最强 | 偏文艺，功能指向弱 |
| **微格教练 / MicroCoach** | 直白 | 零理解成本 | 创新感弱，像工具名 |

**推荐组合**：
- **项目名**：**课镜**
- **副标题**：**AI 微格教学教练 —— 让 AI 当那个会犯错的学生**
- **英文**：**Lesson Mirror · AI Micro-teaching Coach**

### L.2 宣传语（三选一）

1. **"上讲台之前，先给 AI 学生上一课。"**（最推荐：短、有画面、有场景）
2. **"别的 AI 教你知识，我们让 AI 考你的教学。"**
3. **"让师范生在见到真学生之前，先失败十次。"**（最有冲击力，适合答辩开场）

### L.3 核心创新点（对外统一口径，四条）

1. **角色反转：AI 不替代教师，而是扮演"会犯错的学生"**
   别人让 AI 当老师（OpenMAIC/SimClass）、当评委（AI 测评系统）；我们让 AI 当**带着学科迷思概念来上课的反事实学生**。AI 从"教师的替代品"变成"教师的磨刀石"。
2. **可解释的教学行为量化：FIAS 自动编码 + 代码算指标**
   把教育学界用了数十年的 FIAS 九类编码**首次做成可自动运行的服务**（我实测：SimClass 论文用了 FIAS，但其公开实现里**只有一张 FIAS 图片，没有任何代码**）。指标（TT/ST/IDR/SIR）由代码从事件流计算，**可复现、可审计、可申诉**。
3. **"教案—实施—评价"三方一致性对齐诊断**
   把建构一致性做成**结构化对齐矩阵**，直接指出"目标落空 / 游离活动 / 不可评目标"——这是师范生最常犯、却最少被检测的错误。
4. **"训练—评价—反思—改进—再训练"真闭环**
   教案以**校验式 patch** 形式迭代（保留师范生的原创性），反思由**师范生自己写**（AI 只追问），并用**前后两轮的行为指标变化**作为成效证据——而不是满意度问卷。

### L.4 三条"防守型"表述（防止被问倒）

| 评委可能问 | 我们的回答 |
|---|---|
| "这和 ChatGPT 有什么区别？" | "方向相反：ChatGPT 是我问它答；课镜是我讲它挑刺。而且我们的评价锚定 FIAS 九类，指标由代码计算，可复现、可审计，还能点回原文证据——ChatGPT 给不了可申诉的评价。" |
| "AI 评价老师，公平吗？" | "所以我们的每一条结论都挂原文证据，且定位为**发展性评价**而非考核；系统只做 AI 辅助报告，最终解释权在指导教师。文献也证明人类导师反馈在可信度上更高——我们不取代他。" |
| "AI 会让学生变懒吗？" | "反思环节我们**刻意不让 AI 写**，只做苏格拉底式追问，反思报告必须师范生自己写完。教案修订也只出 patch，必须他逐条接受。" |

### M.1 🎯 评分标准对标表（🔴 **本校权威版——以此为准**）

> 🔥 **两条最重要的结论**：
> ① **"落地验证"是初赛 40 分维度里的一个子项** → **没有真实用户测试数据的作品，在本校赛制下会直接丢掉一大块分数。用户测试不是加分项，是必做项（方案见 `08`）。**
> ② **初赛没有独立的"合规与伦理"维度**（与全国赛不同），原创性以「**原创主体说明 + 知识产权证明或研发过程佐证材料**」的形式硬性要求 → **合规仍然要做，但不能靠写伦理设计拿分，只能靠完成度与技术拿分。**
