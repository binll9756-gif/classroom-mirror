## 0. 先说三句结论

1. **技术不难。** 全是拼装成熟件：调用大模型 + 数数算除法 + 存数据库 + 画页面。**没有一项需要你自己发明算法。**（证据见第 3 节：我在一轮对话里搭出了可跑的核心链路。）
2. **但"范围"会压死你。** 你手上的设计是 9 个 Agent + 完整前端 + 两轮闭环 + 用户测试。**3 个人做不完全量版**，必须砍（砍什么见第 6 节）。
3. **真正难的不是写代码，是三件枯燥的事**：① 把 AI 学生调得"像学生"；② 让学生的认知状态前后一致；③ 做真实的用户测试。**这三件事没人能替你，而且它们决定了项目的分数。**

## 1. 这个项目难不难？（分层回答，别听"很简单"也别被吓住）

| 层次 | 难度 | 为什么 |
|---|---|---|
| **搭起核心链路** | ⭐ **不难** | 我已经做完了：知识库 → 虚拟学生 → 状态机 → FIAS 编码 → 指标计算 → 两轮对比，**约 500 行 Python，已跑通并过了 17 项检查** |
| **接上真模型** | ⭐⭐ **简单但磨人** | 代码很简单（就是发一段提示词、收回一段话）；**磨人的是调提示词**——你会反复遇到"学生说话像老师""学生自己变聪明了" |
| **指标计算** | ⭐ **不难（但必须对）** | 就是数数和除法。**但公式错一个符号，整套评价就废了**——所以这部分必须是纯代码 + 有测试 |
| **前端界面** | ⭐⭐⭐ **中等，最占时间** | 5 种图（雷达图、FIAS 迁移矩阵、对齐矩阵、叫答分布、成长曲线）。**新手团队最容易在这里超期** |
| **部署上线（要测试账号）** | ⭐⭐ **中等** | 本地跑和公网访问是两件事；比赛要求评委能自己登录 |
| **用户测试** | ⭐⭐ **不难，但必须有时间** | ≥10 名师范生跑两轮 + 请老师做人工编码比对 |
| **把学生调得像学生** | ⭐⭐⭐⭐ **最难** | 这是真正的技术难点，见下 |

### 真正难的三件事（这才是你要花时间的地方）

**① AI 学生会"自己变聪明"。**
你追问它"为什么"，它第二轮就答对了——因为模型天然想给出正确答案。
但师范生正在练的就是"怎么纠正一个错误理解"，**学生自己好了，训练价值就是零。**
**解法**：把"懂没懂"这件事从模型手里拿走，交给代码的状态机。我的骨架里已经这么做了（`students.py` 的 `state`）。

**② AI 学生说话像老师。**
它会说"从数学本质上看，负负得正体现了……"——**讲得比老师还好。**
**解法**：语言约束（句长上限 + 禁用学术词表）+ 提示词里写死"你是 13 岁学生，不懂教学法，不许总结"。研究已经指出这是行业通病（"语言复杂度过高""不自然地专注"是模拟学生的典型缺陷）。

**③ 你的评价得"可信"。**
如果把整段对话丢给模型问"这个老师讲得好不好"，同一份对话问两次会得到两个答案——**这个评价就废了。**
**解法**：模型只做"这句话属于第几类"的单句判断，**指标由代码算**。这样重复计算的结果完全一致，还可以拿 20 条请老师人工标注做一致性比对。

## 4. 落地路线：四个里程碑（每个都能演示）

> 原则：**每个里程碑结束时，你都要能给人演示一点东西。** 不能演示的阶段等于没做。

### M1 · 让它真的会说话（3~5 天）
**做什么**：加一个 API Key，把 `run_demo.py` 里学生的台词换成真模型生成，但**状态仍由代码控制**。
**能演示**：小林答错，你追问两句，她**仍然坚持错误**（而不是自己好了）。
**要学**：什么是 API Key、什么是 system prompt。

### M2 · 让编码可信（1 周）
**做什么**：把 `rule_classify`（关键词规则）换成一个 LLM 调用：把 FIAS 九类和易混边界写进提示词，让模型只回一个 JSON；**`compute_metrics` 一行都不要改**。然后拿 20~30 条人工标注的语料跑一遍，算一致率。
**能演示**：同一份对话算两次，指标完全相同；和老师的人工标注有可报出的致性。
**要学**：JSON 输出格式、为什么"模型只做分类、指标由代码算"。

### M3 · 让老师看得见（1~2 周）
**做什么**：FastAPI 起接口 + 一个网页。先把页面用**假数据**画出来（这一步不依赖后端，可以并行）。
**能演示**：试讲教室（学生座位区 + 对话流 + 实时 FIAS 标签瀑布 + 被忽略学生计时器）+ 报告页（IDR 指标卡 + 证据高亮）。
**要学**：什么是接口、什么是流式输出（SSE）。

### M4 · 让评委能用（1 周）
**做什么**：公网部署 + 测试账号 + 用户测试（≥10 人）+ 修复现场会崩的地方。
**能演示**：评委用自己的电脑登录，走完一轮。
**要学**：部署（这一步最容易卡，建议找学长或老师帮忙）。

## 5. 每一步要懂的概念（大白话，够用就行）

| 概念 | 大白话解释 | 你在哪会用到 |
|---|---|---|
| **API Key** | 调用大模型的"密码"，按用量付费。**不要写进代码、不要发群里** | M1 |
| **system prompt** | 给模型的"角色设定"，也就是"你是谁、你必须遵守什么规则" | M1（学生会像老师就是这个没写好） |
| **temperature** | 模型说话的随机程度。学生说话要活泼一点（调高），编码分类要稳定（调低到 0） | M1、M2 |
| **JSON 输出** | 让模型用固定格式回答，程序才好处理。**必须做校验 + 失败重试**，否则模型偶尔会多写一句话把程序弄崩 | M2 |
| **事件流** | 把"谁在第几秒说了什么"一条条存下来，**只追加不修改** | 骨架已有 |
| **为什么指标要用代码算** | 因为模型会给你不一样的答案；代码不会 | 骨架已有，这是核心 |
| **SSE（流式输出）** | 让学生的话一个字一个字蹦出来，而不是等 5 秒一起出现——"活人感" | M3 |
| **部署** | 把你的电脑上跑的程序，放到一台别人能访问的机器上 | M4 |

## 6. 必须砍的范围（3 人版，不砍做不完）

| 砍什么 | 怎么砍 | 损失 |
|---|---|---|
| 关键事件的"智能时机判断" | 改成 **2 个手动按钮**（走神、沉默） | 小 |
| 教案修订自动生成 v2 diff | 只出**建议清单 + 理由**，人自己改 | 小 |
| 虚拟学生 4~5 个 | 降到 **3 个**（迷思型 + 沉默型 + 过度积极型） | 小 |
| 反思教练独立 Agent | 用**固定追问模板 + 关键片段回填** | 小 |
| 跨会话成长曲线 | 只做**两轮对比** | 中 |
| 学科教研员 Agent | 明确放二期 | 无 |
| 语音 / 数字人 | **一期完全不做** | 无（增加的是风险，不是分数） |
| 多学科 | 只做初中数学一个课时 | 中（但"可迁移"的理由照样能写） |

### ❌ 绝不能砍的三样

1. **FIAS 编码 + 代码算指标**
2. **两轮试讲对比**
3. **每条结论带原文证据**

**砍掉任何一个，项目就退化成普通聊天机器人。**

## 7. 新手最容易踩的 10 个坑

1. **把 Key 写死在代码里然后传到 GitHub。** → 用环境变量。泄露了立刻去后台吊销。
2. **让模型算指标。** → 指标必须代码算，否则评价不可信、不可申诉。
3. **不做 JSON 校验。** → 模型偶尔会多说话，程序就崩。所有结构化输出都要校验 + 重试。
4. **一口气写完再看。** → 每加一个功能就跑一次、看一眼。我这次的 3 个 bug 都是跑出来才发现的。
5. **先做界面。** → 先让后端出真数据，再套界面。否则你会花一周做一堆没有数据的漂亮页面。
6. **忘了"可复现"。** → 学生随机、事件随机，两轮就没法比较。**同一个 seed 生成同一批学生**（骨架里已经这么做了）。
7. **把所有学生的参与度都设成一样。** → 没有差异就没有"被忽略的学生"这个亮点。
8. **走神/沉默记成一句"学生话语"。** → 会把 ST 算虚高。它是**行为事件**，不进 FIAS 九类。（骨架里已按此处理）
9. **把演示数据当成测试结果。** → 说明书里的成效数据必须来自真实用户测试。**编数据是学术不端。**
10. **忘记去身份化。** → 比赛要求双盲：材料、视频、**现场答辩口播**都不能出现姓名/学院/年级/指导教师。
