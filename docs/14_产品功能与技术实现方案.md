# 产品功能与技术实现方案

> **配套文档**：`13_功能范围冻结与分工（V1.0）.md`（讲"做哪些、谁做"）
> **本文档讲**：能实现什么 → 怎么实现 → 难在哪 → 怎么攻 → 最终长什么样
> **用途**：让全队对"终点"有同一张图。看完你应该能闭眼说出产品的样子。

---

## 0. 一句话

> **把一个师范生对着空教室练课的过程，变成"对着 3 个会犯错的学生练课，并且每一步都有数字可看"。**

---

## 1. 产品最终能实现什么（5 个能力块）

| 能力块 | 一句话 | 用户能感知到的价值 |
|---|---|---|
| **① 读懂教案** | 上传教案 → 自动解析出目标、重难点、**学生可能怎么错**、**教案本身的漏洞** | "它比我先看出这份教案的问题" |
| **② 造出学生** | 生成 3 个带着不同迷思概念、性格各异的学生 | "每个学生都是带着错误来上课的" |
| **③ 撑起课堂** | 学生实时提问、答错、**坚持错误**、走神、抢答 | "这个课堂是活的，不是问答机器人" |
| **④ 诊断教学** | 每句话打 FIAS 标签 → **代码算出指标** → 出带原文证据的报告 | "它不是打分，是有证据的诊断" |
| **⑤ 形成闭环** | 改教案 → 第二轮 → 两轮对比 | "我知道自己到底有没有进步" |

**这五块连起来，才是产品。缺任何一块，它就退化成一个普通教育聊天机器人。**

## 2. 逐功能的实现路径

### F1 教案上传与解析

| 项 | 内容 |
|---|---|
| **怎么做** | 前端上传文件 → 后端用 `pypdf`（PDF）或 `python-docx`（Word）抽出纯文本 → 调一次 LLM，用**固定 JSON Schema** 要求它输出结构化教案 |
| **关键点** | ① **必须做 JSON Schema 校验 + 失败重试**（模型偶尔会多写一句话把解析弄崩）；② 三个字段要有**交叉引用**：`activities[].objective_refs`、`assessments[].objective_refs`——**没有引用，后面就算不出"哪个目标落空了"** |
| **输出契约** | 见 `13` 号文档第 3 节 |
| **技术栈** | `pypdf` / `python-docx` + LLM + Pydantic 校验 |
| **验收** | 上传一份初中数学 PDF，60 秒内出结果，含 ≥3 条迷思概念假设 |

### F2 生成 3 个虚拟学生

| 项 | 内容 |
|---|---|
| **怎么做** | 把 F1 解析出的迷思概念 + 学段语言画像喂给 LLM，生成学生画像；**参与度、原型、语言约束由代码指定**，不由模型自由发挥 |
| **关键点** | **同一个 seed 必须生成同一批学生**（`random.Random(seed)`），否则两轮没法比 |
| **输出** | 学生画像 YAML（已有雏形：`knowledge/misconceptions.yaml`） |
| **验收** | 两次生成结果完全一致；三人迷思概念不同 |

### F3 实时试讲对话（**接真模型**）

| 项 | 内容 |
|---|---|
| **怎么做** | 师范生输入 → 构造 system prompt（**人设 + 认知状态 + 语言约束 + 硬规则**）→ 调 LLM → 拿到台词 → **再走一次状态机更新 state** |
| **关键点** | ⚠️ **状态必须由代码更新，不由模型决定**（见难点 1） |
| **接口** | `students.student_line_online(stu, teacher_text)` 已写好，**但当前 demo 没调用它**——这是 M1 要做的事 |
| **验收** | 连续 10 轮出现：≥1 次答错、≥1 次质疑/超纲、≥1 次走神/沉默 |

### F4 认知状态机（★ 全项目最难）

| 项 | 内容 |
|---|---|
| **怎么做** | 每个学生维护 `state = {understanding, confusion, convinced, patience}`；**每轮由代码更新**；下一轮把它注入提示词 |
| **关键点** | 提示词里必须写死："**你的理解程度由下面这个状态决定，不能因为老师讲了一遍就变懂；要变，必须由状态变化驱动**" |
| **现状** | ✅ **已实现并有测试**（`tests/test_fias.py` 第 4 节验证"答错后不自行变聪明"） |
| **验收** | 第 3 轮答错后，第 8 轮仍表现为未理解 |

### F5 关键事件（2 个手动按钮）

| 项 | 内容 |
|---|---|
| **怎么做** | 老师端点按钮 → 后端写入一条 `event`（`fias=null`）→ 前端显示横幅 |
| **关键点** | ⚠️ **走神是"行为事件"，不是"一句课堂话语"**，所以 `fias` 记 `null`、**不进 FIAS 九类计数**——否则会把学生话语比（ST）算虚高 |
| **验收** | 点击后界面出现事件，并能在报告里被引用 |

### F6 逐句 FIAS 编码

| 项 | 内容 |
|---|---|
| **怎么做** | **方案 A（一期）**：关键词规则分类（`fias.rule_classify`，已实现）+ 抽样人工校验；**方案 B（二期）**：一次 LLM 调用，只回 `{"fias": 6}` |
| **关键点** | ① **只判单句**，不让模型通读后总结（降低出错面）；② 类别必须 1~9，否则重试；③ 易混边界写进规则：**"大家记住，考试要考" → 第 6 类【指令】，不是第 5 类【讲授】** |
| **现状** | 规则版已实现；**已知会判错**（"你来重复一遍我刚才说的"因含"刚才说"被误判为第 3 类）——这正是要上 LLM 的理由 |
| **验收** | 输出每句一个标签；抽样与人工标注可比对 |

### F7 指标计算（★ 必须由代码做）

| 项 | 内容 |
|---|---|
| **怎么做** | **纯 Python**：数数 + 除法。公式：TT=(1~7)/全部、ST=(8~9)/全部、**IDR=(1~4)/(5~7)**、SIR=9/(8+9) |
| **关键点** | 🔴 **绝不许让模型算指标**。模型算的话同一份对话两次给两个数字，评价就废了 |
| **现状** | ✅ **已实现并测试通过**（`kj/fias.py`），含除零保护 |
| **验收** | 同一份对话重复计算，结果完全一致 |

### F8 评价报告（带证据）

| 项 | 内容 |
|---|---|
| **怎么做** | 把 F7 指标 + 教案结构 + 事件流喂给评价 Agent，要求输出**"叙事 + JSON 尾巴"**；每条结论必须带 `evidence_turn_ids` |
| **关键点** | ① **无证据的结论不许出现**；② 反馈必须三段式：**原文证据 → 教育学解释 → 可执行动作**；③ 必须有 ≥1 条正面评价（发展性评价原则） |
| **降级** | JSON 解析失败时，**叙事照常展示、结构化数据不落库**（优雅降级） |
| **验收** | 无证据结论数 = 0 |

### F9 两轮试讲 + 对比

| 项 | 内容 |
|---|---|
| **怎么做** | 第二轮用同一教案修订版、**同一批学生（同 seed）**、同样时长；结束后读两轮 metric 做差 |
| **关键点** | ① **第一轮不显示指标**（防"为指标而表演"）；② 只比"教师纯行为指标"，**TT/ST/SIR 只作情境描述** |
| **现状** | ✅ 对比逻辑已实现（`kj/store.py` 的 `compare()`） |
| **验收** | 显示 IDR / 等待时间 / 抢答率 / 记忆型提问占比 / 被忽略学生数的前后变化 |

### F10 数据落库 + 可重算

| 项 | 内容 |
|---|---|
| **怎么做** | SQLite 三张表：`session` / `turn`（只追加）/ `metric`（派生，可重算） |
| **关键点** | **原始事件永不修改**；指标随时能从事件流重算 → 这就是"评价可审计" |
| **现状** | ✅ 已实现；测试验证"重算两次结果一致" |
| **验收** | 能回答"这个分数怎么来的"，并当场重算 |

### F11 公网部署 + 测试账号

| 项 | 内容 |
|---|---|
| **怎么做** | 后端 FastAPI + 前端打包 → 部署到一台能被访问的机器；**内网穿透是最省事的兜底** |
| **关键点** | **不需要域名、不需要备案**；但要准备"载入历史会话"入口，防现场网络问题 |
| **验收** | 手机热点 + 别人电脑各登录一次成功 |

## 3. 数据流（一条链路看懂）

```
 教案 PDF
   │ ① pypdf 抽文本
   ↓
 结构化教案（目标/重难点/迷思概念/薄弱点）
   │ ② 生成学生
   ↓
 3 个虚拟学生（画像 + 认知状态机）
   │ ③ 师范生试讲
   ↓
 ┌──────────────────────────────────────────┐
 │  每一轮：老师说话 → 代码判"是否提问"      │
 │        → 选目标学生 → 学生回应（LLM）      │
 │        → 代码更新学生 state               │
 │        → 两个人各写一条 turn 进事件流      │
 └──────────────────────────────────────────┘
   │ ④ 编码：turn 补上 fias 标签
   ↓
 turn 序列  ──⑤ 纯代码统计──→  metric 指标
   │                              │
   │ ⑥ 评价 Agent                  │ ⑦ 落库（可重算）
   ↓                              ↓
 评价报告（带证据）          session / turn / metric
   │ ⑧ 第二轮
   ↓
 两轮对比（compare）
```

## 4. 技术架构

| 层 | 用什么 | 负责什么 |
|---|---|---|
| **前端** | Next.js / 或先用最简单的 HTML+ECharts | 5 个页面、SSE 流式渲染、图表 |
| **后端** | **FastAPI（Python）** | 接口、文件解析、会话管理、导出 |
| **编排** | 先**直接函数调用**，暂不引入 LangGraph | 备课 → 试讲 → 编码 → 评价 → 对比 |
| **模型** | 任何 OpenAI 兼容端点（DeepSeek / 通义 / 智谱） | 教案解析、学生台词、评价措辞 |
| **规则/代码** | 纯 Python | **FIAS 指标**、统计、对比、事件触发、校验 |
| **知识** | YAML / Markdown 文件 | 迷思概念库、语言画像、编码规则 |
| **存储** | SQLite | 事件流 + 派生指标 |

> ⚠️ **一期不要引入 LangGraph、不要上向量库、不要上 Redis**。
> 单份教案可以整篇进上下文；状态就是几个函数的顺序调用。**少一个组件就少一类现场故障。**

## 5. 难点清单（按难度排序，含攻克办法）

### 难点 1 🔴 AI 学生"自己变聪明"（最难）

| 项 | 内容 |
|---|---|
| **现象** | 上一轮学生答错了，下一轮被追问，**它就答对了** |
| **为什么难** | 模型的本能是"给出正确答案"。师范生练的正是"怎么纠正错误理解"，**学生自己好了，训练价值归零** |
| **为什么纯提示词压不住** | 因为在多轮对话里，模型看到自己前面答错了，会倾向"修正"自己 |
| **解法** | 把"懂没懂"从模型手里拿走：<br>① 学生维护 `state = {understanding, confusion, convinced, patience}`；<br>② **每轮由代码更新**（不是模型）；<br>③ 下一轮把 state 注入提示词，并写死"**理解程度由状态决定，不能因为老师讲了一遍就变懂**"；<br>④ 只有满足条件（耐心耗尽 **且** 老师用了"采纳想法/举例子"）才允许 `understanding` 上升 |
| **现状** | ✅ **已实现 + 有测试断言** |
| **谁攻** | P1 引擎 |

### 难点 2 🟠 AI 学生"说话像老师"

| 项 | 内容 |
|---|---|
| **现象** | 学生张口就是"从数学本质上看，负负得正体现了……"——**讲得比老师还好** |
| **为什么难** | 模型的默认语域是"知识渊博的成年人" |
| **解法** | ① **语言约束**：句长上限 + **禁用学术词表**（`language_profile`，已实现）；② 提示词硬规则："你就是个 13 岁学生，不懂教学法，**不许总结教学内容，不许讲得比老师好**"；③ 错误**必须来自迷思概念库**，不许自由发挥 |
| **验证** | 有公开研究指出"语言复杂度过高""不自然地专注"是模拟学生的典型缺陷——**这就是我们的验收清单** |
| **谁攻** | P1 引擎 |

### 难点 3 🟠 行为可控性（该走神时走神，该沉默时沉默）

| 项 | 内容 |
|---|---|
| **现象** | 不做控制时，AI 学生会**抢着说话**或**一直沉默**；跑两次结果完全不同 |
| **为什么难** | 模型倾向于"礼貌地等待"，且行为带随机性 |
| **解法** | ① **走神由代码触发**（按参与度 + 冷却），不由模型自觉；② **发言闸门**：没被点名且是沉默型 → 不说话；③ 走神**记 `fias=null`**，不进九类计数；④ **固定 seed** 保证可复现 |
| **现状** | ✅ 已实现（含走神冷却，避免刷屏） |
| **谁攻** | P1 引擎 |

### 难点 4 🟠 FIAS 编码准确性

| 项 | 内容 |
|---|---|
| **现象** | 模型判断"这句话属于第几类"会出错 |
| **典型分歧** | "大家记住，考试要考" → **6 指令**（不是 5 讲授）；"很好！那谁能说说为什么？" → **4 提问**（按主导意图）；教师自问自答 → 只记 4，且**不产生 8/9 类**，同时计入"抢答率" |
| **解法（五道防线）** | ① 规则卡把易混边界写死；② **只判单句**；③ Schema 约束输出格式；④ 类别必须 1~9 否则重试；⑤ **抽样人工校验**（请老师在不看 AI 结果的前提下独立标注） |
| **现状** | 规则版已实现；**LLM 版待做**；一致率数据待测 |
| **谁攻** | P2 数据与评价 |

### 难点 5 🟡 指标必须可复现（不能交给模型）

| 项 | 内容 |
|---|---|
| **现象** | 如果让模型"读完对话给个 IDR"，同一份对话两次会得到两个数字 |
| **为什么致命** | 评价就不可信、不可申诉、不可审计 |
| **解法** | **模型只做单句分类，指标由代码数**。这条已经写进代码注释与架构设计 |
| **现状** | ✅ 已实现（含除零保护）+ 有测试 |
| **谁攻** | P2（**但这是纪律问题，全队都要守**） |

### 难点 6 🟡 评价不能是空话

| 项 | 内容 |
|---|---|
| **❌ 不能出现** | "你可以更加关注学生""课堂氛围可以更活跃" |
| **✅ 应该出现** | "在第 3 次学生表达困惑后（第 7 分钟），你直接进行了概念解释，**没有进一步追问学生原有理解**。下一轮可先追问'你为什么认为负负得正就是规定？'再解释。——依据：FIAS 第 5 类连续出现 4 次，期间无第 4 类与第 3 类" |
| **解法** | 强制**三段式**：原文证据 → 教育学解释 → 可执行动作；生成阶段就检查"有没有 `evidence_turn_ids`"，没有就判不合格重试 |
| **谁攻** | P1（评价 Agent 文案） |

### 难点 7 🟡 公网部署（工程性难点，不是技术难点）

| 项 | 内容 |
|---|---|
| **现象** | 本地跑得好好的，别人就是打不开 |
| **为什么难** | 涉及内网、防火墙、端口、进程守护；新手最陌生 |
| **解法** | ① 内网穿透兜底（最省事）；② 或学校服务器；③ **不需要域名、不需要备案**；④ 准备"载入历史会话"入口，防现场网络问题 |
| **谁攻** | P3 前端与交付 |

## 6. 与同类智能体的对比（优势在哪）

> 这一节是**答辩与说明书的弹药**。所有对比都基于**实际查证过的公开信息**，不是推测。
> ⚠️ 使用规则：**主动承认别人做过什么**，再精确划出我们的位置。**别声称"首创"。**

### 6.1 先分类：市面上有 5 类"教育智能体"

| 类别 | 代表 | 它做什么 | 它的用户 |
|---|---|---|---|
| ① 通用大模型 | ChatGPT / DeepSeek | 你问它答 | 任何人 |
| ② AI 备课 / 教案生成 | instructional_agents、edu-agent | 帮你写教案、出题、做课件 | **教师** |
| ③ AI 评课 / 教学测评 | 师范院校的"教学技能 AI 测评系统" | 录课 → 分析 → 给老师打分 | **教师（被评价）** |
| ④ AI 虚拟课堂 | OpenMAIC、SimClass | AI 当老师/同学，给学习者上课 | **学习者** |
| ⑤ AI 模拟学生（研究侧） | Student GPT、TeachTune | 让 AI 扮演学生 | **研究者 / 教师** |
| **我们** | **课镜** | **AI 当"会犯错的学生"，给师范生练** | **师范生** |

### 6.2 逐类对比

**对比 ①：通用大模型**

| | 通用大模型 | 课镜 |
|---|---|---|
| 角色方向 | 你问它答 | **你说它挑刺** |
| 评价标准 | 自由文本，**同一节课两次不同评语** | 锚定 **FIAS 九类**，指标由代码算，**可复现** |
| 状态 | 无，翻篇即失忆 | **事件流**：谁在第几秒说了什么，可回放 |
| 产出物 | 聊天记录 | **报告 + 反思 + 教案 v2**（可归档） |
| 可申诉 | 不能 | 每条结论**可点回原文**，可提异议 |

**对比 ②：AI 备课 / 教案生成类**

| | 它们 | 课镜 |
|---|---|---|
| 在做什么 | **事务替代**：帮你写教案、出题、做课件 | **能力训练**：训练你**现场教学**的能力 |
| 目标 | 减负 | **提升** |
| 产出 | 教案、课件、测验 | **你的教学行为数据** |

> 一句话：**它们在替老师干活，我们在训练老师本身。**

**对比 ③：AI 评课 / 教学测评类（★ 最需要划清界限）**

这类已有成熟产品——某师范院校的系统已服务 **1000+ 师范生、近 2000 次测评**，并与多位学科专家的独立评分做过一致性验证、入选省级优秀案例。
**如果我们的卖点是"AI 给师范生打分"，就是重复劳动。**

| | 现有 AI 测评系统 | 课镜 |
|---|---|---|
| **AI 的角色** | **裁判**（给你打分） | **陪练**（先陪你练，再给你看数据） |
| **数据来源** | 摄像头 + 麦克风 + 视频分析（眼神、语速、语调） | **只用教案 + 文本试讲记录** |
| **隐私成本** | 高（采集影像） | **零影像采集** |
| **输出形态** | 自然语言结论 + 雷达图 | **可审计的结构化指标**（事件流可重算） |
| **轮次** | 评价**一次** | **两轮闭环**，用前后变化证明改进 |
| **人的角色** | 被动接受评价 | 主动在对抗中练 + **自己写反思** |

> **最关键的一句：他们的 AI 是裁判，我们的 AI 是陪练。**

**对比 ④：AI 虚拟课堂**

| | 它们 | 课镜 |
|---|---|---|
| **用户** | **学习者**（AI 当老师/同学给他上课） | **师范生**（AI 当学生让他练） |
| **AI 扮演谁** | 老师、好同学 | **会犯错、会坚持错误的学生** |
| 指标方向 | 学习者的知识掌握度 | **教师的教学行为**（IDR 等） |
| 与我们的关系 | **借鉴其调度架构**（MIT 许可，已在 README 声明），但**目的完全相反** | — |

> 📌 **一个容易误读的数字**：那项研究里 AI 课堂的 **SIR 高达 0.896**（远超专家教师的 0.121）——**那不是"AI 学生更主动"，而是设计出来的**。引用时务必说明，否则显得没读懂文献。

**对比 ⑤：AI 模拟学生研究（⚠️ 必须诚实）**

| | 它们已做过的 | 课镜的位置 |
|---|---|---|
| **让 AI 扮演带迷思概念的学生** | **已有**：Student GPT（*IJAIED* 2025）用聊天机器人扮演"比例推理有迷思概念的初中生" | 我们**不是首创**这个机制 |
| **教师创建并检查模拟学生** | **已有**：TeachTune（面向教师，30 名科学教师参与验证） | 重心不同：它偏"配置与检查"，我们偏"在对抗中训练" |
| **我们的差异** | — | ① 接成**完整闭环**（训练→评价→反思→教案迭代→再训练）；② **FIAS 行为量化**；③ **面向师范生的教学反思与专业发展** |

> ✅ **正确说法**："**该机制已被单点验证；但把它做成'反事实学生 → FIAS 行为量化 → 反思 → 教案迭代'的师范生训练闭环，尚无公开工作。**"
> ❌ **禁止说**："我们首创让 AI 犯错。"

**对比 ⑥：传统微格教学 + 同学互评**

| | 同学互评 | 课镜 |
|---|---|---|
| 反馈质量 | "挺好的""普通话标准"（碍于情面） | 带证据的具体行为诊断 |
| 能否复现难点 | 不能（今天 A 恰好答错，明天 B 答对了） | **能**（错误来自迷思概念库，可稳定复现） |
| 有无数据 | 无 | 有，可比较、可追踪 |
| 社交压力 | 有 | **无**（可以放心讲砸） |

### 6.3 优势的本质：三条（不是功能多）

**优势 1｜角色反转**
> 别人让 AI 当老师（替人讲课）、当评委（给人打分）；**我们让 AI 当"带着迷思概念来上课的学生"**。
> AI 从"教师的替代品"变成"**教师的磨刀石**"。

**优势 2｜评价可审计（技术含量最高）**
> **LLM 只做单句分类，指标由代码计算；事件流只追加、指标可重算。**
> 所以能回答："**这个分数怎么来的？**"——当场从第一句话重算给你看。
> **同一份对话重复计算，结果永远一致。**
> 👉 **这一条同类几乎都做不到**（很多人习惯让模型"读完对话给个分数"）。

**优势 3｜真闭环 + 增值评价**
> 不是评一次就结束，而是**两轮对比**，用**教师纯行为指标**的前后变化证明改进。
> 对应政策里"**开展多维度的过程评价、增值评价**"的要求。

**附加优势｜零影像采集**
> 主动放弃摄像头 / 人脸 / 眼神分析——**隐私与伦理成本最低**，而且**不需要任何硬件**。
> 同类系统大多依赖录课设备。

### 6.4 也要诚实说劣势（这段能救答辩）

| 劣势 | 实话 |
|---|---|
| **没有规模验证** | 现有 AI 测评系统已服务 1000+ 师范生；**我们目前 0 用户** |
| **文本不如视频** | 它们能捕捉眼神、语速、板书；我们只用文本，**看不到非语言行为** |
| **模拟学生真实性** | 公开研究指出 LLM 模拟学生有"语言复杂度高""不自然地专注"等缺陷，**我们还在调** |
| **编码准确性** | FIAS 自动编码的一致率**尚未验证**，需要人工抽样比对 |

> **主动承认这些，比被问出来强十倍。** 评委问这些不是要否定你，是想看你知不知道边界在哪。

### 6.5 可以直接对评委说的 30 秒版

> "现在市面上的 AI 教育产品分两类：一类让 AI 当老师替人讲课，一类让 AI 当评委给人打分。
> 但研究显示 AI 教师的'间接引导比'只有 0.058，专家人类教师是 1.473——**差 25 倍，AI 很会讲、几乎不会引导**。
> 所以我们的定位是反过来的：**不让 AI 当老师，让 AI 当那个会犯错的学生。**
> 师范生对着它试讲，系统用 FIAS 给每句话编码、**用代码算出教学行为指标**——注意指标不是模型算的，所以**可复现、可审计**；
> 改完教案再讲第二轮，**用两轮数据的对比证明有没有真的改进**。
> 一句话：**别人让 AI 替代教师，我们让 AI 磨砺教师。**"

| 里程碑 | 目标 | 完成标志 |

## 10. 一句话总结

> **这个产品的独特性不在"AI 能说话"，而在三件事：**
> **① 学生的"错误"来自学科迷思概念（不是随机胡说）；**
> **② 学生的"懂没懂"由代码控住（不会自己变聪明）；**
> **③ 教学行为的"有没有改善"由代码算出来（可复现、可审计）。**
>
> **丢掉任何一条，它就变成普通的教育聊天机器人。**
