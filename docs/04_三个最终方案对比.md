# 三个最值得做的最终方案 + 四维度差异分析

> 配套：`01_项目调研与技术拆解.md`（六项目调研与技术可借鉴清单）｜`02_微格教练_方案设计.md`（A–G）｜`03_微格教练_MVP与技术实现.md`（H–M）
> 三个方案都在"人工智能 + 师范教育"主轴上，但**押的是三种完全不同的赌注**：**训练** / **沉浸** / **证据**。

## 方案一：课镜 —— AI 微格教学教练

### 一句话
让 AI 扮演**带着学科迷思概念来上课的反事实学生**，师范生对着它反复试讲，系统量化教学行为、生成反思追问、自动迭代教案，形成"训练—评价—反思—改进—再训练"闭环。

### 解决的教育痛点
- 真实试讲机会稀缺（一个师范生在校期间平均只有 1~2 次完整上台机会，导师要带几十上百人，无法逐次细致观察）；
- 同伴互评流于形式（实证研究里的原话是"**互评困境**"：'你的课件做得挺好看的''普通话挺标准的'，评价隔靴搔痒）；
- **现行 AI 模拟的最大实证短板**：师生互动**以师范生为中心、学生主动性不足**；**课堂管理与学生参与效能感待加强**（宛平、顾小清，《现代教育技术》2025(10)，单组实验 n=27）；
- 模拟学生**"不自然地专注"**、语言复杂度偏高（BEA 2025 教师访谈指出的五大真实性缺陷）——**乖学生练不出诊断能力**。

### 用户
- 主要：**师范专业本科二至四年级学生**（正在修《微格教学》《学科教学论》、即将教育实习）；
- 次要：**学科教学论 / 微格教学课程指导教师**（获得可归档的过程性证据）；
- 潜在：新入职教师、县域教师培训。

### 核心功能
1. 上传教材/教案 → 自动解析教学目标（ABCD）、重难点、学情假设、**迷思概念**、**设计薄弱点**；
2. 生成 **3~5 个反事实虚拟学生**（迷思型 / 沉默走神型 / 过度积极型 / 深度质疑型），每个带认知状态机与语言约束；
3. 实时文本试讲：学生**提问、答错、坚持错误、质疑、走神、沉默**；
4. 关键事件注入（走神、集体沉默、超纲提问）；
5. **FIAS 九类自动编码** + 代码计算 TT/ST/**IDR**/SIR + 提问层次 + 等待时间 + **叫答公平性**；
6. 可解释评价报告（每条结论挂原文证据）+ 建构一致性对齐矩阵；
7. 苏格拉底式反思追问（**不代写反思**）；
8. 教案 patch 式迭代（带理由，逐条接受/拒绝）；
9. 二轮试讲 + 前后行为指标对比 + 成长曲线。

### Agent 架构
**1 个调度者 + 8 个专职 Agent**（详见 `02` 的 D/E 节）：
`D0 流程导演` → 备课侧 `A1 教案分析师 → A2 虚拟学生铸造工坊 → A3 场景导演` → 试讲侧 `A4 虚拟学生 ×N` → 课后侧 `A5 行为编码员 → A6 评价员 → A7 反思教练 → A8 教案修订师`（`A9 学科教研员` 二期）
编排：**LangGraph StateGraph**；一次请求只跑一轮 `director → student`，多轮由前端序列化驱动。

### 技术难度
**中**。难点集中在三处且都有现成参照：
- 多学生调度不重复、不抢话（← OpenMAIC `peer-context.ts`、MAIC-Core Director）；
- 学生**认知状态跨轮一致**（需要自建状态机，这是最难的一处）；
- FIAS 编码一致性（LLM 分类 + 代码算指标 + 抽样人工校验）。
**不需要**：ASR/TTS、数字人、视频分析、向量库。

### 开发工作量
🔴 **本校通知硬约束：团队 ≤3 人。** 折算后（原 4 人的 24 人周 ÷ 3）＝ **3 人 × 8 周**（约 300~360 人时）。关键路径：多学生调度、编码准确性、闭环与稳定性。
若压缩到 **3 人 × 5 周**：砍掉关键事件注入（改为 2 个按钮）、砍掉教案 patch 自动落版（只出建议清单）、只做 3 个学生。

### 比赛展示效果
**中高**。张力来自"**学生会顶嘴**"和"**被忽略的学生**"两个画面。但要警惕一个陷阱：**如果界面上主要是一个对话流，评委会立刻归类为"这不就是 ChatGPT"**。破解方式：把**学生座位区 + 实时 FIAS 标签瀑布 + 被忽略计时器**做成常驻视觉元素；高潮放在 3:15 的"打脸报告"（IDR 0.12 vs 专家 1.473）。

### 创新点
1. **反事实虚拟学生**（别人造"乖学生"，我们造"会犯错的学生"）
   ⚠️ **表述纪律**：学术上已有先例（**Student GPT / Student ChatGPT**, *IJAIED* 2025，用聊天机器人扮演"比例推理有迷思概念"的初中生），所以**不能说"我们首创让 AI 犯错"**。正确说法是："**该机制已被单点验证，但把它做成'反事实学生 → FIAS 行为量化 → 反思 → 教案迭代'的师范生训练闭环，尚无公开工作。**"
2. **FIAS 自动编码**（实测空缺：SimClass 论文大量使用 FIAS，其公开实现里**只有一张 FIAS 图片、零代码**）；
3. **建构一致性对齐矩阵**（把"目标偏离"从一句话变成一张结构化矩阵）；
4. **叫答公平性 + 等待时间**（几乎无人做，技术上极简，教育学依据硬）；
5. **反思不代写**（教育理念层面的加分 + 伦理护身符）。

### 风险
| 风险 | 等级 | 对策 |
|---|---|---|
| 被评委认为"就是 ChatGPT 套壳" | **高** | 视觉重做（座位区/瀑布/计时器常驻）+ 报告页证据高亮 + 现场演示"学生顶嘴且坚持错误" |
| 学生太配合 → 演示不出对抗 | 中 | 走神由**代码触发**；状态机强制"答错不解悟"；Demo 用固定教案 |
| 评价可信度被质疑 | 中 | 指标公式公开 + 抽样人工一致性 + 可点击回原文 + 可重算 |
| 工作量低估（前端可视化 5 种图） | 中 | **3 人分工下前端必须专职**（一人专门负责界面），且 UI 打磨前不做任何"好看但没用"的动效 |
| 现场网络 | 中 | 预跑数据一键回放 + 录屏备份 + 降级路径 |

## 方案二：临场 —— 课堂关键事件应变训练舱

### 一句话
不做完整的一节课，只做**最难的那 40 秒**：AI 导演会不断制造教学突发事件（走神、纪律冲突、超纲质疑、实验失败、家长当场质问），师范生必须在压力下即时应变，系统评估其**课堂管理**与**应变决策**。

### 解决的教育痛点
- 师范生最怕的不是"讲不出来"，而是"**讲着讲着出事了**"：学生走神、有人抬杠、实验失败、突然被问超纲问题；
- 而**实证研究明确指出：模拟课堂提升了教学效能感，但"课堂管理效能感"恰恰是待加强的那一项**（宛平、顾小清 2025）；
- 现有项目全部在做"顺利的一节课"，**没有人专门训练"出事了怎么办"**；
- 课堂管理能力目前在师范培养中主要靠"实习时真出事再学"——**成本最高、最不可控**。

### 用户
- 主要：**即将教育实习的师范生**（最需要临场能力）；
- 次要：班主任技能训练、新教师入职培训；
- 潜在：教师资格证面试（结构化答辩 + 试讲应变）备考人群。

### 核心功能
1. 从教案生成 **3~5 个"高危时刻"**（基于知识点难度与学生画像预测哪里最容易出事）；
2. **事件牌系统**：每张牌有触发条件、压力等级、观察指标；
3. 师范生在有限时间内做**决策**（不是"讲课"，而是"选择怎么办"）：冷处理 / 点名 / 追问 / 调整进度 / 幽默化解；
4. 系统记录**决策时延**、**选择的策略类型**、**后续效果**（AI 学生的情绪与理解度变化）；
5. 多轮"事件链"：一次处理不当会**引发连锁反应**（学生更闹、更多人走神）；
6. 复盘：**决策树回放**——"你当时还有哪 4 种选择，各自可能的结果"；
7. 应变策略库 + 优秀案例对照。

### Agent 架构
**3 个 Agent 就能跑**（最轻）：
- `E1 事件导演`（Event Director）：决定何时、向谁、抛什么事件（可**半脚本化**：代码触发 + LLM 生成具体台词）；
- `E2 学生演员团`：3~5 个学生，带情绪状态机（闹 → 更闹 / 被安抚）；
- `E3 应变评估员`：评价决策时延、策略类型、效果链、替代方案。
（可选 `E4 班主任顾问`：给"如果是老教师会怎么做"的对照）

### 技术难度
**中高**。难点是"**可控的意外**"：
- 事件既要**看起来随机**，又要**可复现**（Demo 不能翻车）→ 必须用"**半脚本**"：事件序列码 + LLM 只负责台词润色；
- 连锁反应需要**学生情绪状态机 + 规则引擎**（不能全靠 LLM 自由发挥）；
- 现场节奏极难控：**AI 太温和没戏，太激进显得假**。

### 开发工作量
🔴 **同样受"团队 ≤3 人"约束**：折算后 ＝ **3 人 × 7 周**（比方案一略少，因为不用做完整评价体系与教案迭代）。但**调参时间会吃掉一半**——事件强度、触发时机、连锁逻辑需要大量人工试跑。**实际风险可能到 3 人 × 9~10 周。**

### 比赛展示效果
**最高**。这是三个方案里**唯一能在 5 分钟里让评委笑、让评委紧张、让评委记住**的方案：
- "学生当场顶嘴"、"全班走神"、"突然有人举手问超纲问题"——**有冲突就有戏剧性**；
- 复盘页的"**决策树回放**"（你当时还有 4 种选择）视觉极强；
- 可以现场让评委**出一张事件牌**（互动环节），现场感拉满。

### 创新点
1. **从"讲一节课"转向"处理一个事件"**——训练粒度的原创切分；
2. **"关键事件"从研究概念变成可操作的产品机制**（华东师大研究把它作为三要素之一，但没有做成产品）；
3. **决策树回放**（反事实教学推理）——几乎无人做；
4. **连锁反应机制**（一次处理不当引发更大的乱）——真实且有教学意义。

### 风险
| 风险 | 等级 | 对策 |
|---|---|---|
| **被评委认为"娱乐化/游戏化，教学严谨性不足"** | **高** | 必须把"事件 → 教学管理理论 → 评价指标"三者绑定（每个事件标注对应的课堂管理理论，如 Kounin 的涟漪效应）；演示时先讲理论再演示 |
| 演示节奏失控（AI 抽风、事件不触发/触发太密） | **高** | 半脚本化 + 固定事件序列 + 彩排 10 遍以上 |
| 评价体系单薄（只有"决策时延 + 策略类型"，撑不起 25 分的"教学融合"） | 中 | 必须补：事件分类学 + 策略库 + 与《教师专业标准》的对应 |
| 工作量被低估（调参时间） | 中 | 预留整整 1.5 周只做调参，不排任何新功能 |
| 与"教师资格证面试/班主任技能大赛"已有产品撞车 | 低 | 检索确认（本次未检索该细分方向） |

## 方案三：课迹 —— 教学行为证据链与教案自动迭代

### 一句话
不造虚拟学生，只做**证据**：把师范生的一次试讲（教案 + 逐句话语记录）变成**可审计的教学行为证据链**——FIAS 编码、建构一致性对齐矩阵、叫答公平性、等待时间——并据此自动产出教案 v2 与成长档案。

### 解决的教育痛点
- 师范生收到的反馈大多是**笼统、不可复现、无法追踪**的（"讲得不错""再多互动"）；
- 教师教育长期缺乏**可累积的过程性证据**（师范专业认证、教育实习考核都需要，但现在是靠人工填表）；
- 现有 AI 评课系统（广西师大）证明了价值，但它**依赖摄像头/麦克风硬件**，部署重、隐私成本高，且**输出是自然语言结论而非可审计的结构化证据**；
- 师范生**看不见自己的教学行为**：他不知道自己只叫了前排、不知道自己 6 次提问全是记忆型。

### 用户
- 主要：**师范生**（自测）+ **学科教学论/微格课指导教师**（快速批阅全班试讲记录）；
- 次要：**教研室 / 师范专业认证材料负责人**（需要过程性证据）；
- 潜在：教师招聘面试评课、教师培训档案。

### 核心功能
1. 导入试讲记录（**文本记录为主**，可选手工上传已有的逐字稿/听课记录）；
2. **FIAS 九类自动编码** + 代码计算 TT/ST/IDR/SIR、提问层次、等待时间、叫答分布；
3. **建构一致性对齐矩阵**（目标 / 教案活动 / 实际发生 / 评价手段，四色诊断）；
4. **行为证据链**：每条结论挂可点击的原文证据，可申诉；
5. **教案 patch 自动迭代**（带理由与依据，逐条接受/拒绝）；
6. **成长档案**：多次试讲的指标曲线 + 一键导出"过程性证据包"（PDF/Word）；
7. 教师批量视图：一个班 30 人的试讲指标横向对比（**这一条对指导教师极有吸引力**）。

### Agent 架构
**4 个 Agent，最精简**：
- `C1 编码员`（逐句 FIAS 分类，LLM）
- `C2 指标计算器`（**纯代码，不用 LLM** ← 这是它最"硬"的地方）
- `C3 评价与对齐诊断员`（量规打分 + 对齐矩阵 + 证据链）
- `C4 教案修订师`（JSON Patch）
（可选 `C5 反思教练`）

### 技术难度
**低**。三个方案里最低。
- 最大技术点只是**编码一致性**（LLM 分类 + 抽样校验）；
- **甚至可以不接实时 LLM**：编码用批处理，评价可用固定量规 → **离线也能出结果，演示最稳**；
- 不需要多 Agent 调度、不需要状态机、不需要实时流。

### 开发工作量
**3 人 × 3~4 周**（约 120~160 人时）。若只做"编码 + 指标 + 报告 + 导出"这四件，**2 人 2 周也能出可演示版本**。

### 比赛展示效果
**中**。优势是"专业感"爆棚：**FIAS 9×9 迁移矩阵热力图**、**雷达图**、**四色对齐矩阵**、**班级横向对比**——评委（教育学背景）一看就知道"这学生懂教育"。
劣势是**缺少"活物"**：屏幕上没有会说话的人，5 分钟里比较难制造情绪起伏。**必须靠"打脸数据"和"证据高亮"制造张力**（例如：把一位师范生的试讲记录投上去，当场显示"你整节课没叫过后排 3 个人"）。

### 创新点
1. **可审计的证据链**：事件流 + 可重算指标，把 AI 评课从"黑箱结论"变成"透明证据"（这是对广西师大路线的最直接超越）；
2. **建构一致性对齐矩阵**（结构化检测，非自然语言结论）；
3. **不依赖摄像头/麦克风**：**主动放弃视频分析＝隐私成本极低**，反而成为合规优势（"我们没有采集任何影像数据"）；
4. **叫答公平性 + 等待时间**（教师看不见的行为盲区）；
5. **教师批量视图 + 过程性证据包导出**（对接师范专业认证，这是"推广价值"的硬抓手）。

### 风险
| 风险 | 等级 | 对策 |
|---|---|---|
| **创新性被认为不足**（广西师大已做过 AI 评课） | **高** | 必须把"**可审计 + 对齐矩阵 + 公平性 + 零影像**"四点做成核心叙事，绝不提"我们也是 AI 评课" |
| 演示缺"活人"，5 分钟难有记忆点 | **高** | 用真人案例（一位师范生的真实试讲记录）演示"打脸时刻"；准备**班级横向对比**一屏 |
| 输入从哪来（没有系统录课，逐字稿难获得） | 中 | MVP 提供"边导入边试讲"的轻文本输入；或接入已有的微格教室文本记录；**这是本方案最大的产品风险** |
| 变成"Excel 加了个 AI" | 中 | 视觉必须专业（热力图 + 对齐矩阵 + 证据高亮跳到原文） |

## 四维度差异分析（讲清差异，不选"最好"）

> 评分的四个维度：**创新性 / 可实现性 / 演示效果 / 师范教育契合度**。下面逐维度说明三个方案的**差异性质**，而不是打分排名。

### 维度一：创新性

| | 方案一 课镜 | 方案二 临场 | 方案三 课迹 |
|---|---|---|---|
| 创新性的**来源** | **装配方式**：三个已有零件（虚拟学生 + FIAS + 教案迭代）拼成闭环 | **切入角度**：把训练粒度从"一节课"切到"一个事件" | **证据形态**：把 AI 评课从"结论"变成"可审计证据" |
| 创新性的**硬度** | 中高（有实测空缺背书：FIAS 自动化确实没人做） | 高（少见，但需防"娱乐化"质疑） | 中（易被归为"广西师大已做过"） |
| 被质疑时的**应对难度** | 低（可当场演示"学生顶嘴且坚持错误"） | **高**（很难自证"不是游戏"） | **高**（很难自证"不是重复劳动"） |
| **最怕的一句评委话** | "这不就是 ChatGPT 加了个评分？" | "这是游戏还是教学？" | "广西师大不是已经做了吗？" |

**差异结论**：**方案二的"新"最锐利但最难守，方案三的"新"最容易被抹平，方案一的"新"最平衡**——因为它的三个零件单独都不新，但"反事实学生 → 行为量化 → 教案迭代"这条闭环线确实没人完整做过。

### 维度二：可实现性

| | 方案一 课镜 | 方案二 临场 | 方案三 课迹 |
|---|---|---|---|
| 技术难度 | 中 | **中高**（可控的意外最难） | **低** |
| 名义工作量 | **3 人 × 8 周** | **3 人 × 7 周** | **3 人 × 4 周** |
| **实际风险工作量** | 3 人 × 8 周（可控） | **3 人 × 9~10 周**（调参时间不可控，占一半） | 3 人 × 4~5 周（可控） |
| 关键不确定性 | 学生状态一致性、多学生调度 | **事件强度与节奏调参**、连锁逻辑 | 输入数据来源、编码一致性 |
| 最坏情况 | 闭环只跑通一半（仍可演示） | **演示不触发/太温和 → 没戏** | 变成"报表工具" |
| 对抗 LLM 不确定性的手段 | schema 校验 + 状态机 + 代码触发 | **半脚本化**（必须） | 批处理 + 固定量规（最稳） |

**差异结论**：**方案三是"保底可用"，方案一是"中等风险中等回报"，方案二是"高风险高波动"**。方案二的风险不在写代码，而在**调参**——这部分工作量在学生项目里最容易被低估，也最容易压垮进度。

### 维度三：演示效果

| | 方案一 课镜 | 方案二 临场 | 方案三 课迹 |
|---|---|---|---|
| 情绪张力 | 中高（学生顶嘴/被忽略） | **最高**（冲突、连锁、戏剧性） | 中（靠"打脸数据"） |
| 5 分钟内能被记住的画面 | **被忽略学生灰化 + IDR 0.12 vs 专家 1.473** | **学生当场顶嘴 / 决策树回放** | **FIAS 热力图 + 对齐矩阵 + 班级横向对比** |
| 能否现场互动 | 可（让评委当"学生"提一个问题） | **强**（让评委出一张事件牌） | 弱 |
| 最大演示风险 | 界面被误认为"聊天框" | **动画/事件不触发** | 缺"活物"，显得静态 |
| 视觉资产丰富度 | 高（5 种图 + 对话 + 计时器） | 中高（事件横幅 + 决策树） | **高**（热力图/雷达图/矩阵/曲线） |
| 需要彩排次数 | 5~10 次 | **10~15 次** | 3~5 次 |

**差异结论**：**方案二"上限最高、下限最低"；方案一"波动小、可控"；方案三"下限最高、上限一般"**。若团队里没有擅长现场节奏控制的人，方案二的演示风险会显著放大。

### 维度四：师范教育契合度

| | 方案一 课镜 | 方案二 临场 | 方案三 课迹 |
|---|---|---|---|
| 对应师范培养环节 | **微格教学 / 学科教学论**（试讲循环，最正统） | **教育实习前的应急能力训练**（对应实习痛点） | **教学评价 / 教育实习考核 / 师范专业认证** |
| 用到的教育学工具 | FIAS + 建构一致性 + 布鲁姆 + 等待时间 + 迷思概念 | 课堂管理理论（需自行绑定，如 Kounin 涟漪效应） | **FIAS + 建构一致性**（最纯粹） |
| 训练的核心能力 | 诊断 + 追问 + 公平 + 应变（**综合**） | **课堂管理与应变**（单点但极深） | **自我认知与反思**（元认知） |
| 与实证研究短板的对齐 | ✅ **全部命中**（学生主动性、课堂管理效能感、策略转化） | ✅ **精准命中"课堂管理效能感待加强"** | ⚠️ 命中"策略转化"，但**不训练学生的主动性** |
| 人机协同的形态 | AI 报告 + 导师复核 + 学生逐条确认 | AI 导演 + 学生即时决策（**弱人机协同**——导师难介入） | AI 报告 + 导师批量复核（**协同最自然**） |
| 伦理风险 | 低（无影像、反思不代写） | 中（游戏化可能引发"是否严肃"的质疑） | **最低**（无影像、无实时生成、纯文本） |
| 对"师范教育"而非"AI 教育"的体现强度 | **最强** | 强 | 强（但偏"评价学"） |

**差异结论**：**方案一是"师范教育本体"（微格教学就是这个循环）；方案二是"师范教育痛点专精"（课堂管理是实证短板，但需要额外补理论绑定才不会显得轻浮）；方案三是"师范教育基础设施"（评价与证据，最稳但离"训练"远一层）**。

### 综合：三者的性质差异（不是优劣）

| | 方案一 课镜 | 方案二 临场 | 方案三 课迹 |
|---|---|---|---|
| **赌的是** | **训练** | **沉浸** | **证据** |
| 团队适配 | 均衡型团队（有前端 + 有 Agent + 有教育学同学） | **需要有擅长现场表达和节奏控制的成员** | **人数少/时间紧/求稳**的团队 |
| 一句话总结差异 | "**把 AI 变成陪练，练出诊断能力**" | "**把 AI 变成导演，练出临场能力**" | "**把 AI 变成镜子，看见自己的盲区**" |

## 我的建议：不要三选一，而是"一主两辅"

**理由**：三个方案的成本结构完全不同，且**不冲突**——方案三的评价引擎几乎是方案一的一个子模块，方案二的一张事件牌几乎不用改代码就能塞进方案一的课堂。

**推荐组合（一个系统，三个卖点）**：

```
主体（占 60% 工作量）= 方案一「课镜」
   └── 评价引擎直接采用方案三的全套（FIAS 编码 + 代码算指标 + 对标矩阵 + 公平性）
        └── 收益：技术实现 25 分 + 教学融合 25 分 同时拿住

亮点模块（占 20%）= 方案三的"班级批量视图 + 过程性证据包导出"
   └── 收益：直接命中"应用成效与推广价值 15 分"，且答辩时能讲"可跨校推广"

演示彩蛋（占 10%）= 方案二的一张关键事件牌（走神/顶嘴）
   └── 收益：5 分钟 Demo 的记忆点（3:15 的"打脸时刻"靠它制造）

留白（占 10%）= 稳定性与彩排
```

**为什么这个组合成立**：
- 三者共用**同一套事件流 + 同一套指标**，不是三个项目拼在一起；
- 方案三的价值在方案一里**天然存在**（它就是方案一的 `A5+A6`），提取出来单做成"班级视图"几乎零额外成本；
- 方案二只取**一张事件牌**（而非全套事件系统），风险从"高"降到"低"，但记忆点保留；
- 这样对外只有**一个项目名、一个 Demo、一份说明书**，符合比赛要求；对内则是**三个维度的得分点全覆盖**。

**唯一要注意的**：**别把三个方案的完整功能都做进去**。学生项目最常见的死法是把"亮点"全做一半——**结果什么都能演示，什么都不稳**。上面 60/20/10/10 的比例就是用来防止这件事的。
