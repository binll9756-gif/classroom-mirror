## 0. 先给结论（三句话）

1. **这个方向值得做，但"AI 评课"这条路已经被走透了**——广西师大已经做到千人验证、与专家评分一致、入选省级优秀案例。所以**我们不能做"AI 打分器"，必须做"AI 陪练 + 闭环"**。
2. **我们的护城河不在模型，在三样东西**：① **反事实虚拟学生**（会犯错、会走神、会质疑，而不是乖学生）；② **可解释的行为量化**（FIAS 九类编码 + IDR/等待时间/叫答公平性）；③ **教案自动迭代闭环**（试讲→评价→反思→教案 v2→再试讲）。
3. **宣传口径必须收敛**：文献证据显示"教学行为表现"能显著提升（d≈0.90），但"自我效能感/PCK"提升弱（d≈0.20~0.35）。**所以我们说"把试错成本降到 0"，不说"提升教学水平 N 倍"。** 说得越克制，答辩越稳。

## A. 这个项目是否具有足够的比赛创新性？

**结论：中等偏上，但需要三个具体设计来"立住"，否则会被评委归为"又一个 AI 评课系统"。**

### A.1 为什么"不够"创新——必须先承认

- **AI 评课已成熟**：广西师范大学"师范生教学技能AI测评系统"（陆声链团队）已服务 1000+ 师范生、近 2000 次测评，与 4 学科专家背对背评分高度一致，入选"广西信息化赋能高质量发展优秀案例"。**如果我们的核心卖点是"AI 给师范生打分"，那是重复劳动。**
- **AI 虚拟学生已有先例**：SimClass（NAACL 2025）已做出 4 类 AI 同学；OpenMAIC 已把它做成可运行产品；TeachTune 已经做了"面向教师的模拟学生生成与检查工具"。
- **AI 自动改教案也有先例**：instructional_agents（EACL 2026）基于 ADDIE 自动生成与优化整门课程材料。

三个零件都不新。**新的只能是"装配方式"。**

### A.2 为什么"够"创新——三个真正没人做透的点

| # | 创新点 | 为什么别人没做 | 为什么评委认 |
|---|---|---|---|
| 1 | **反事实虚拟学生（会犯错、会走神、会坚持错误）** | ⚠️ **这个机制已有先例，必须诚实**：**Student GPT / Student ChatGPT**（*IJAIED* 2025）已用聊天机器人扮演"比例推理有迷思概念"的初中生。但**没有**一个是把它接进"行为量化 → 反思 → 教案迭代 → 再训练"的**师范生闭环**。另外 BEA 2025 明确指出模拟学生"**不自然地专注**"是五大缺陷之一 | 一句话说清："**我们不做 AI 老师，我们做会犯错的学生；而且我们把它接成了闭环**" |
| 2 | **把 FIAS 的 IDR 变成师范生的训练 KPI** | 我实测查证：**SimClass 论文里的 FIAS 是人工研究流程，MAIC-Core 代码里完全没有**（grep `FIAS` 零命中，只有一张 `assets/FIAS.png` 图片）。这意味着"**自动化的 FIAS 编码**"目前是空缺的 | 有硬数据支撑：AI 教师 IDR=0.058，专家人类教师 IDR=1.473，**差 25 倍**。这个对比图放在 PPT 上极其震撼 |
| 3 | **"教案—实施—评价"三方一致性对齐诊断** | 广西师大只做到"一句话指出目标偏离"；OpenMAIC 只在生成时约束 assessment alignment。**没有人把它做成结构化对齐矩阵** | 这是**教育专业性的体现**，评委（大概率是教育学/教学法背景）一看就懂、一看就服 |

### A.3 加分项（让创新性从"中等偏上"到"稳进奖"）

- **叫答公平性检测**（"被忽略的学生"可视化）——几乎无人做，且直接呼应师德与教育公平；
- **等待时间（wait time）训练**——教育学经典结论，技术实现只是一个计时器，投入产出比最高；
- **"AI 拒绝替你想"的反思设计**——反思由师范生自己写，AI 只追问。这是**教育理念层面的加分点**，也是伦理答辩的护身符。

### A.4 创新性的正确表述（写进说明书的话）

> 现有工作或让 AI 扮演教师（OpenMAIC、SimClass），或让 AI 扮演评委（广西师大 AI 测评系统）。**本项目反向定位：让 AI 扮演"会犯错的学生"，把 AI 从"替代教师"变成"磨砺教师的磨刀石"。**

## B. 和普通 ChatGPT 相比，核心差异是什么？

**六条差异，从浅到深，按"评委可能追问的顺序"排列。**

### B.1 角色方向相反（最直观）

| | 普通 ChatGPT | 课镜 |
|---|---|---|
| 谁的立场 | 站在**回答者**一侧，为你服务 | 站在**学生**一侧，**给你制造困难** |
| 你的动作 | 提问 | **讲课** |
| 它做什么 | 给你答案 | **提问你、答错、质疑你、走神** |

> 演示时说这一句就够：*"ChatGPT 是你说它答；课镜是你说它挑刺。"*

### B.2 有结构化标准，评价可复现（最硬）

ChatGPT 的反馈是**自由文本、不可复现、无基准**——同一个老师两次得到不同的评语，无法比较、无法申诉。

课镜的评价锚定 **FIAS（弗兰德斯互动分析）九类编码**（这一体系在教育学界用了数十年）：
1 接受情感｜2 表扬鼓励｜3 采纳想法｜4 提问｜5 讲授｜6 给出指令｜7 批评｜8 学生应答｜9 学生主动发起

→ 输出**可计算、可对比、可复现**的指标：TT、ST、**IDR**、SIR、提问层次分布、等待时间、叫答分布。

### B.3 有状态、有事件流、可回放（最容易被忽略但最重要）

试讲全程被记录成**结构化事件流**（谁在第几秒说了什么、属于 FIAS 第几类、"学生 B"在第 6 分钟被忽略）。因此可以：
- **回放**：点击报告里任一结论，高亮对应原文；
- **对比**：第一轮 vs 第二轮指标变化；
- **追踪**：多次训练的成长曲线（**支撑比赛要求的"量化数据、对比成效"**）。

ChatGPT 没有状态，翻篇即失忆。

### B.4 产出物是"教学资产"而不是"聊天记录"

课镜的最终产物是三份可归档的东西：
1. **结构化评价报告**（带证据链的雷达图 + 指标卡）
2. **师范生自己写的教学反思**（AI 只追问，不代写）
3. **教案 v2（带 diff 与修订依据）**

→ 可直接作为**教育实习/微格教学课程的过程性证据**。聊天记录当不了证据。

### B.5 一致性约束（这是 LLM 应用的工程门槛）

普通 ChatGPT 扮演学生时会**前后矛盾**（前面答错了，后面又答对了）、会**说老师话**（语言复杂度远高于 K12 学生）。

课镜给每个虚拟学生维护**认知状态机**：`先备知识 / 当前困惑点 / 是否被说服 / 情绪`。**"我不懂了"这件事必须被记住。** 这正是 BEA 2025 指出的"逻辑不一致"缺陷的对症解法。

### B.6 伦理与合规内建

教育评价是**高风险场景**。课镜的每条结论都强制挂**原文证据锚点**（可申诉），并定位为"人类导师之前的预训练"，报告可交导师复核。ChatGPT 无法承担这个责任。

## C. 如何体现"师范教育"而不是普通 AI 教育

**这一节是拿分关键——评分标准里"教学融合与应用设计"占 25 分。**

### C.1 训练对象不同：不训练"知识掌握"，训练"教学行为"

| | 普通 AI 教育 | 课镜（师范教育） |
|---|---|---|
| 被提升的人 | **学生** | **师范生（未来的教师）** |
| 优化目标 | 学会某个知识点 | 学会**教**这个知识点 |
| 核心 KPI | 正确率、掌握度 | **IDR、等待时间、提问层次、叫答公平性、目标达成度** |
| 失败的样子 | 学生答错 | **教师不会诊断学生的错误** |

### C.2 评价标准用"师范教育的法定/学术工具"，不用自创指标

- **FIAS 弗兰德斯互动分析**——课堂话语分析的国际通行量表（我们用它做行为编码）
- **微格教学的经典循环**——试讲 → 评价 → 反思 → 修改教案 → 再试讲（我们把它做成产品流程）
- **建构一致性（Constructive Alignment）**——目标/活动/评价三者对齐（我们把它做成对齐矩阵）
- **布鲁姆认知层次**——提问层次分布
- **等待时间（wait time）**——教育学经典
- **学科迷思概念库**——《义务教育课程方案和课程标准》配套的学科教学知识

### C.3 交付形态对接师范生培养体系，而不是"一个 App"

- 产出可归档的**过程性证据包**（评价报告 + 反思 + 教案迭代记录）→ 对接**教育实习/微格教学课程**的考核材料；
- 对应**《师范生教师职业能力标准》**中的"教学实践能力"与"反思与发展能力"；
- 可对接**师范类专业认证**的"实践教学"材料要求。

### C.4 训练"教师的高阶能力"，不是"教师的事务性工作"

现有教育 AI 大多在做**事务替代**（备课、出题、批改、写教案 = instructional_agents、edu-agent 的定位）。课镜训练的是**不可替代的现场能力**：
- 诊断（从一个错误答案反推认知结构）
- 追问（问出学生的真实想法）
- 留白（等 3 秒而不是抢答）
- 公平（注意到被忽略的学生）
- 应变（走神、超纲提问、纪律问题）

### C.5 用"教研的语言"说话

课镜的评语结构强制三段式：**证据（原文片段）→ 解释（教育学依据）→ 改进建议（可执行动作）**。这是中小学评课/教研的规范表达，而不是"AI 味"的泛泛而谈。

### C.6 教育伦理内建（评分标准里"合规与伦理"占 15 分）

| 风险 | 课镜的对策 |
|---|---|
| 算法评价教师不公平 | 每条结论带证据锚点，**可解释、可申诉**；定位为"发展性评价"而非"考核性评价" |
| 取代人类导师 | 显式设计"**AI 报告 → 导师复核批注**"环节；文献已证人类反馈的"可信度与有用性"更高，我们把它作为设计前提而非失败 |
| 学生数据隐私 | **第一版不做人脸/眼神/录像分析**（广西师大用摄像头，我们不碰），只用师范生自己上传的教案与试讲文本 |
| 未成年人形象 | 虚拟学生是**角色**，不采集任何真实学生数据、不生成对真实学生的评价 |
| AI 代劳导致能力退化 | 反思**不代写**，只追问；教案修订必须**师范生逐条确认**才落版 |
| 生成内容标注 | 所有 AI 生成内容标注来源与生成时间 |

## D. 应该设计哪些 Agent？

**设计原则**：① 每个 Agent 只做一件事（OpenMAIC 的 Evaluator 注释给了理由："同一个 system prompt 会自己打自己"）；② 评价类 Agent 必须输出**结构化 schema**，失败可降级；③ **能不用 LLM 就不用**（OpenMAIC 单 Agent 时走纯代码）。

### D.1 架构总览

```
                       ┌──────────────────────────────┐
                       │   D0 · 流程导演 Director      │  ← 调度者，不"讲课"
                       │  (LangGraph StateGraph 节点)  │     选人 + 选动作，代码兜底
                       └──────────────┬───────────────┘
                                      │
   ┌──────────────────────────────────┴──────────────────────────────────┐
   │                         备课阶段（离线，一次）                        │
   │  A1 教案分析师 ──→ A2 虚拟学生铸造工坊 ──→ A3 场景导演                │
   └──────────────────────────────────┬──────────────────────────────────┘
                                      │
   ┌──────────────────────────────────┴──────────────────────────────────┐
   │                        试讲阶段（在线，实时轮次）                      │
   │  师范生（人） ──发言──→   A4 虚拟学生 ×N（3~5 个）                    │
   │      ↑                       ↓ 每轮产出：话语 + 行为 + 内部状态变更     │
   │      └──── D0 决定"下一个谁说话、做什么动作" ←── A3 关键事件注入        │
   └──────────────────────────────────┬──────────────────────────────────┘
                                      │ 事件流落库（结构化，逐轮）
   ┌──────────────────────────────────┴──────────────────────────────────┐
   │                          课后阶段（离线，一次）                        │
   │  A5 教学行为编码员 ──→ A6 教学评价员 ──→ A7 反思教练 ──→ A8 教案修订师 │
   │                              ↑                              │
   │                        A9 学科教研员（可选）                  │
   └─────────────────────────────────────────────────────────────┘
                                      │
                            教案 v2 → 回到试讲阶段（闭环）
```

### D.2 Agent 清单（9 个，MVP 做 6 个）

| ID | Agent | MVP? | 为什么必须/可以不做 |
|---|---|---|---|
| D0 | **流程导演 Director** | ✅ | 无它则多学生发言会乱、会重复、会抢话 |
| A1 | **教案分析师** | ✅ | 没有目标/重难点，后面全部无从评价 |
| A2 | **虚拟学生铸造工坊** | ✅ | 核心差异所在（反事实学生） |
| A3 | **场景导演 / 关键事件注入器** | ✅（简化版） | 没有它就没有"课堂管理"压力，退化成"乖学生问答" |
| A4 | **虚拟学生（运行时 ×N）** | ✅ | 主体 |
| A5 | **教学行为编码员** | ✅ | 没有它，评价就是"AI 随便说说" |
| A6 | **教学评价员** | ✅ | 主要交付物 |
| A7 | **反思教练** | ✅（可极简） | 闭环的关键一环，且伦理加分 |
| A8 | **教案修订师** | ⚠️ 二期可简化为一版"修订建议" | 闭环的最后一段；MVP 可先出"建议清单 + 人工改" |
| A9 | **学科教研员（专业挑错）** | ❌ 二期 | 加分项，非必需 |

> **注意**：A3 和 A9 是"可选但很香"。如果时间紧，把 A3 降级成"3 个预设关键事件按钮"（不用 LLM 实时判断），依然能演示。

## E. 每个 Agent 负责什么（含输入输出契约）

> 契约写法借鉴 OpenMAIC 的 Evaluator：**叙事文本 + JSON 尾巴**，JSON 解析失败时叙事仍可展示、结构化数据不落库（"优雅降级"）。所有 JSON 输出都必须经过 schema 校验 + 失败重试（参考 MAIC-Core `gen_structure.py:67-195` 的 parse→validate→retry 范式）。

### D0 · 流程导演 Director（调度者，不是说话的人）

- **职责**：每一轮决定"**下一个谁说话 + 做什么动作**"，并保证不重复、不抢话、节奏合理。
- **输入**：可用学生列表（含 role / 参与度 / 优先级）+ 本轮已发言摘要 + 课堂进度（讲到哪个环节）+ 关键事件队列 + 隐藏状态（谁被忽略了多久）
- **输出**：`{ next_speaker_id, action, reason }`，`action ∈ {提问, 回答, 质疑, 走神, 沉默, 争论, 举手}`
- **关键工程细节**（三条都来自源码实证）：
  1. **LLM 只选人，代码兜底**：MAIC-Core 的 Director 输出被强约束为"只包括演员的名字"，再用 `in agent_name_list` 校验；OpenMAIC 在单 Agent 场景**完全不用 LLM**。我们照做：`next_speaker_id` 必须命中候选集合，否则走代码回退（选优先级最高者）。
  2. **必须排除刚发过言的人**（MAIC-Core `readScript.py:119-148`）。
  3. **注入"本轮别人说了什么"**（OpenMAIC `peer-context.ts`），否则每个学生都会重复打招呼、复述老师的话。提示词骨架可直接借用其五条 MUST。
- **为什么不合并进 A4**：调度需要全局视野（谁被忽略了），而单个学生只有局部视野（我懂不懂）。

### A1 · 教案分析师（Lesson Analyst）

- **职责**：把上传的教材/教案，解析成结构化教学设计，**并且标出教学设计的薄弱点**。
- **输入**：教案文件（PDF/DOCX/PPTX）+ 学科 + 学段
- **输出**（严格 JSON）：
  ```json
  {
    "subject": "初中数学", "grade": "七年级下", "duration_min": 40,
    "objectives": [{"id":"O1","text":"...","level":"理解","abcd":{"audience":"学生","behavior":"...","condition":"...","degree":"..."}}],
    "key_points": ["..."], "difficult_points": ["..."],
    "prior_knowledge": ["..."],                    // 学情假设：学生已会什么
    "likely_misconceptions": [{"id":"M1","text":"会把'负负得正'当作纯记忆规则套用","source":"课标/学科教学知识"}],
    "activities": [{"id":"A1","name":"情境导入","objective_refs":["O1"],"minutes":5}],
    "assessments": [{"id":"E1","type":"随堂提问","objective_refs":["O1"],"bloom":"记忆"}],
    "design_gaps": ["O2 没有任何评价手段对应（不可评目标）"]      // ← 设计薄弱点，提前给出
  }
  ```
- **关键要求**：`objective_refs` / `activities` / `assessments` 的**交叉引用必须存在**——这是后面"建构一致性对齐矩阵"的数据基础。**这三个字段的引用完整性，是这个 Agent 存在的意义。**
- **参考**：instructional_agents 的 ADDIE 分析与 Catalog（学生档案）设计；OpenMAIC `k12-core-literacy-planning` 的学科迷思概念文档。

### A2 · 虚拟学生铸造工坊（Student Casting）

- **职责**：生成 3~5 个**有明确差异、且差异有教育学意义**的虚拟学生。
- **输入**：A1 的输出（重点是 `likely_misconceptions` 与 `prior_knowledge`）+ 班级难度档位
- **每个学生的输出契约**：
  ```json
  {
    "id":"S1", "name":"小林", "archetype":"迷思型",
    "prior_knowledge":"会用公式但不懂算理",
    "misconception":"M1: 把负负得正当作记忆规则",
    "personality":"安静、怕答错、被点名会紧张",
    "engagement_base": 0.5,                        // 0~1，参与基线
    "language_profile":{"grade_band":"初中","max_sentence_len":18,"forbidden_words":["认知负荷","维度"]},
    "behavior_tendencies":["被提问时先犹豫 3~5 秒","答错后会坚持一次","不会主动举报自己的错误"],
    "state": {"understanding":0.2,"confusion":0.7,"emotion":"焦虑","convinced":false}
  }
  ```
- **必须覆盖的 4 类原型**（这是"反事实"的落地）：
  | 原型 | 教育意义 | 行为特征 |
  |---|---|---|
  | **迷思型** | 训练**诊断**能力 | 坚定地给出错误答案，并用错误逻辑解释 |
  | **沉默型 / 走神型** | 训练**课堂管理**与公平 | 不主动发言、被点名才回神、会走神（触发关键事件） |
  | **过度积极型** | 训练**节奏控制** | 抢答、跑题、占用课堂时间（类似 SimClass 的"显眼包"） |
  | **深度质疑型** | 训练**学科深度** | 提出超纲/挑战性问题、问"为什么"（对应"思考者"） |
- **验收标准（直接来自 BEA 2025 的五大缺陷）**：语言复杂度受 `language_profile` 约束；有情绪；会走神；**认知状态跨轮次一致**；错误来自迷思概念库而非随机胡说。
- **参考**：SimClass 论文的"角色 × 行为维度（TI/ID/EC/CM）"矩阵；MAIC-Core `readScript.py:449-507` 的 `{identity, role}` 结构。

### A3 · 场景导演 / 关键事件注入器（Scene Director）

- **职责**：控制课堂节奏，并在合适时机**注入"关键事件"**制造真实教学压力。
- **关键事件类型**（这是华东师大研究里的核心要素之一，也是"课堂管理效能感"短板的靶向解法）：
  - 学生走神 / 交头接耳 / 低头玩东西
  - 学生提出超纲问题（"老师，那如果除数是 0 呢？"）
  - 学生坚持错误理解（"可是我觉得就是这样的"）
  - 集体沉默（提问后无人回应）
  - 学生答对了但说不出理由
  - 时间压力（"还剩 3 分钟，你这节课还有 2 个目标没讲到"）
- **MVP 简化版**：**不做 LLM 实时判断，改成"事件牌"**——每个事件有触发条件（如"连续 2 次提问只有同一学生回答"）+ 时机窗口，由代码触发。**这样可控、可复现、Demo 不会翻车。**
- **参考**：SimClass 论文 §3.3 的 Function Executor（函数可插拔 + 时间窗 τ 触发）。

### A4 · 虚拟学生（运行时 ×N）

- **职责**：以"学生"的身份实时发言——**提问、回答、答错、质疑、沉默、走神**。
- **输入**：自己的画像 + 认知状态 + 课堂历史（格式化）+ 本轮同伴已说的话 + 老师刚说的话 + Director 指定的动作类型
- **输出**：`{ speech, fi_as_hint, behavior, state_delta }`
  - `speech`：学生口吻的台词（受语言约束）
  - `behavior`：本轮外部行为（如 `走神`、`举手`），供编码员使用
  - `state_delta`：自己的认知/情绪变化（如 `{"confusion":+0.1,"convinced":false}`）→ **写回状态，保证跨轮一致**
- **硬规则**（写进 system prompt）：
  1. **只说自己年级会说的话**，禁止专业术语
  2. **不许替老师总结**，不许讲得比老师好
  3. **错误必须来自自己的迷思概念**，且**答错后至少坚持一轮**
  4. **不确定时要表现出不确定**（"呃……是不是……"）
  5. 身份是学生，**永远不要评论"这个教学设计如何"**
- **参考**：OpenMAIC `registry/store.ts` 的 persona 写法（教学/学习风格 + 语气 + 长度约束）；MAIC-Core 的 `format_history_for_agent`（`<!-- 演员名 -->内容`）。

### A5 · 教学行为编码员（Interaction Coder）

- **职责**：把试讲全程逐句打上 **FIAS 九类标签**，并计算指标。**这是整个系统可信度的地基。**
- **输入**：结构化事件流（谁、何时、说了什么、学生行为）+ A1 的教案结构
- **输出**：
  ```json
  {
    "turns": [{"t":42,"speaker":"teacher","text":"...","fias":4,"evidence_span":[42,58]},
              {"t":61,"speaker":"S1","text":"...","fias":8}],
    "metrics": {"TT":0.71,"ST":0.29,"IDR":0.12,"SIR":0.33},
    "bloom_distribution": {"记忆":5,"理解":2,"应用":0,"分析":0,"评价":0,"创造":0},
    "wait_times": [1.1, 0.8, 2.3, 3.4],
    "call_distribution": {"S1":3,"S2":0,"S3":1},          // ← 叫答公平性
    "teacher_questions": 7,
    "open_questions": 1
  }
  ```
- **为什么要拆成独立 Agent**：它与评价 Agent 的**输出契约和失败模式完全不同**。编码是"逐条分类"（可批量、可校验、可人工抽查），评价是"综合判断"。**混在一起会导致两者互相污染**（OpenMAIC 的 Evaluator 注释就是这个理由）。
- **可信度设计（关键）**：
  1. **先分类再计算**：LLM 只做"逐条分类"，指标由**代码计算**——这样指标 100% 可复现，LLM 只在分类环节可能出错；
  2. **抽样人工校验**：报告里注明"编码抽样一致性"，可邀请指导老师标注 20 条做核对（**这就是"与专家评分一致性"的证明方式**，参考广西师大的做法）；
  3. **边界规则写死在提示词里**：如"教师说'大家记住，考试要考' → 第 6 类【给出指令】，不是第 5 类【讲授】"。
- **参考**：SimClass 论文 Table 1 的九类定义与四个指标公式（TT/ST/IDR/SIR）；它用 GPT-4 打标并评估了打标质量（论文 §4.2.1）。

### A6 · 教学评价员（Evaluator）

- **职责**：把编码结果 + 教案解读成**师范生能看懂、能改的评语**，并给出多维评分。
- **输入**：A5 的指标 + A1 的教案结构 + 试讲事件流
- **输出**：**叙事文本 + JSON 尾巴**
  ```json
  {
    "scores": {"目标达成":3.2,"提问质量":2.1,"互动引导":1.8,"课堂管理":2.6,"时间控制":3.5,"评价一致性":2.0},
    "strengths": [{"claim":"...","evidence_turn_ids":[12,13],"theory":"FIAS 第2类 表扬鼓励"}],
    "improvements": [{"claim":"...","evidence_turn_ids":[31],"theory":"等待时间<1.5s",
                      "action":"下次提问后默数 3 秒再点名"}],
    "alignment_matrix": {...},              // 见下
    "risk_flags": ["整节课 S2 从未被叫到（8 分钟）"]
  }
  ```
- **三条铁律**：
  1. **每条结论必须挂 `evidence_turn_ids`**（可点击高亮原文）——没有证据的结论不许出现；
  2. **用"证据 → 解释 → 可执行动作"三段式**写建议，禁止"语言亲切、互动良好"这类空话；
  3. **必须包含至少一条正面评价**（发展性评价原则，避免打击师范生）。
- **它同时产出"建构一致性对齐矩阵"**（也可以拆成独立小 Agent）：
  | 教学目标 | 教案中的活动 | 试讲中实际发生 | 评价手段 | 诊断 |
  |---|---|---|---|---|
  | O1 理解算理 | A2 情境探究 | ✅ 出现（t=180） | 随堂提问（理解层） | 对齐 |
  | O2 会用公式解方程 | A3 例题演练 | ❌ **未出现** | 无 | **目标落空 + 不可评** |
  | — | A4 拓展讨论 | ✅ 出现（t=1500） | — | **游离活动（无目标对应）** |
- **参考**：instructional_agents `src/evaluate.py`（多视角评估 + 量规打分 + JSON 约束 + 重试）；OpenMAIC Evaluator 的"叙事 + JSON 尾巴"契约与降级策略。

### A7 · 反思教练（Reflection Coach）

- **职责**：**不写反思**，只**追问**，逼师范生自己写出反思。
- **输入**：A6 的评价 + 试讲关键片段（尤其是失败片段）
- **输出**：3~5 个递进式追问 + 师范生自由书写的输入框
- **追问设计**（示例）：
  1. "你在第 3 分钟问了'负负得正记住了吗'，学生小林点头了。**但她在第 7 分钟又做错了。这说明什么？**"
  2. "你当时如果改成问'为什么负负得正'，你觉得小林会怎么回答？"
  3. "整节课你叫了 4 次小林、0 次小周。如果再给你 1 分钟，你会怎么安排？"
- **硬规则**：不给答案、不写结论、不评价师范生的反思写得好不好（只问"还有吗"）。
- **教育价值**：这是"AI 时代教师主体性"的体现，也是伦理答辩的护身符。
- **参考**：AI-Tutor-Agent `prompts/student_heuristic_tutor.md` 的"防泄题 + 等待学生作答 + 三次自检"写法。

### A8 · 教案修订师（Lesson Reviser）

- **职责**：基于评价与反思，产出**教案 v2**，且**每条修改都要写明理由与依据**。
- **输出契约（关键）**：不是重新生成一份教案，而是**结构化的修订补丁（JSON Patch 风格）**：
  ```json
  {"op":"add","path":"/activities/2","value":{"name":"追问算理环节","objective_refs":["O1"],"minutes":5},
   "reason":"补足 O1 的算理理解，避免纯记忆","evidence":["t=180 学生仅点头未解释"]}
  ```
- **为什么必须用 Patch 而不是"重新生成"**：① 师范生能看懂"改了什么"（diff 视图）；② 保留师范生的原创性（不是 AI 重写他的教案）；③ 可逐条接受/拒绝（人在环）。
- **工程要求**：每条 patch 应用后必须**校验教案结构完整性**（引用的 objective_id 必须存在），不合法则拒绝并重试——参考 OpenMAIC v0.3.1 的"**校验式 JSON Patch 编辑**"。
- **参考**：OpenMAIC 的 Edit-with-AI（校验式 JSON Patch）；instructional_agents 的 `optimize.py` 与 Copilot 模式（每阶段人工反馈）。

### A9 · 学科教研员（可选，二期）

- **职责**：从学科专业角度挑错（如"负负得正的解释在数学上不严谨"）。
- **为什么放二期**：它需要学科专家知识库支撑，且与 A6 的边界容易重叠（**两个 Agent 都说"你讲错了"会让报告显得混乱**）。

## F. 第一版必须做（MVP 范围，砍到不能再砍）

**判断标准：删掉它，闭环就断了 → 必须做；删掉它，只是"少了个亮点" → 二期做。**

| # | 功能 | 为什么不能砍 |
|---|---|---|
| 1 | 上传教案/教材（**单文件、PDF/DOCX/TXT 即可**）→ 结构化解析 | 入口。注意：**用 `pypdf`/`pdfplumber`，不要 PyMuPDF（AGPL）** |
| 2 | 输出教学目标 / 重点 / 难点 / **迷思概念** / 学情假设 | 后面一切评价的参照系 |
| 3 | 生成 **3 个**差异明确的虚拟学生（迷思型 + 沉默型 + 过度积极型） | 核心差异点。**3 个够了，别做 6 个** |
| 4 | **实时文本试讲**：学生能提问、能答错、能质疑、会走神 | 主体体验 |
| 5 | 学生**认知状态跨轮一致**（答错了就还是不懂） | 文献点名的头号缺陷，必须解决 |
| 6 | 逐句 **FIAS 九类编码**（LLM 分类）+ **指标由代码计算** | 可信度地基 |
| 7 | 4 个核心指标：**TT / ST / IDR / SIR** + 提问次数 + 等待时间 + 叫答分布 | 支撑"量化数据、对比成效" |
| 8 | **一次评价报告**：雷达图 + 指标卡 + **每条结论挂原文证据** | 主要交付物 |
| 9 | **反思追问 3 问**（不代写） | 闭环 + 伦理加分 |
| 10 | **教案修订建议**（MVP 可先出"建议清单 + 每条 patch 的理由"，不强制自动落版） | 闭环最后一段 |
| 11 | **第二轮试讲 + 前后对比**（IDR / 等待时间 / 叫答分布） | 🔥 **"闭环"的证明，也是全项目最有说服力的一屏** |
| 12 | 数据落库 + 成长曲线 | 比赛要求"量化数据、对比成效" |
| 13 | 关键事件**结构化提示**（至少 2 种：走神、集体沉默） | 课堂管理靶点；MVP 用代码触发，不用 LLM |

## G. 哪些功能可以以后再做（明确说"不做"也是加分）

| 功能 | 为什么放后面 |
|---|---|
| **语音实时交互（ASR/TTS/打断）** | 技术风险高、Demo 现场翻车概率大；**文本先跑通闭环**。二期用 FunASR + 流式 TTS |
| **数字人 / 口型 / 表情（Live2D、VRM）** | 好看但不增加教育价值；且 Live2D 是**专有许可**（有营收门槛），VRM（three-vrm, MIT）更安全 |
| **摄像头视频分析（眼神/手势/走位）** | 广西师大已做且做重了；**我们要刻意避开**——这是隐私风险最高、伦理成本最大的模块 |
| **多学科支持** | 先做**一个学科**（建议初中数学：迷思概念清晰、评分客观、你校数学师范生基数大） |
| **多人协同 / 一个班多个师范生互相听课** | 并发与权限复杂，收益低 |
| **对接真实班级数据 / 学生画像** | 涉及真实未成年人数据，伦理与合规成本极高 |
| **移动端 / 小程序** | 演示用桌面 Web 即可 |
| **AI 自动生成课件 PPT** | 是另一个赛道（教学辅助）的问题，不是我们的问题 |
| **AI 教研员 / AI 同行教师（多视角评课团）** | 香但容易让报告变乱（多个 Agent 说不同的话）；二期做"评课圆桌" |
| **长期成长档案跨课程、跨学期** | 需要时间积累数据，比赛周期内做不出真实效果 |
| **自动出题/作业批改** | 赛道不同，别分散火力 |

> **一条重要纪律**：**每加一个功能，都要问"它能不能在 5 分钟 Demo 里被看见"**。看不见的功能，对比赛是净负收益（增加风险、摊薄资源）。
