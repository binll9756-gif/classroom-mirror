## 01 一句话理解项目

**官方版（写进说明书用）：**

> 面向师范生的 **AI 教学实训与课堂行为诊断智能体**——让师范生随时对着 AI 模拟学生试讲，试讲后系统自动对课堂互动做 FIAS 编码分析，指出具体的教学行为问题并给出可执行的改进建议，再由师范生进行第二轮试讲，用行为指标的前后变化验证改进是否真的发生。

**大白话版（给外行听）：**

> 师范生最难的是"没机会上台练"。我们做了一个"AI 学生陪练"：你对着几个 AI 学生讲课，这几个学生会提问、会答错、会犯迷糊、会追问；讲完之后系统帮你把整节课的互动拆开看——**你是自己讲得多，还是让学生想说？你是问完就自己答，还是等了三秒？你是不是从头到尾只叫了前排那一个学生？** 然后你改一改，再讲一遍，系统给你看两轮的差别。

**最短版（电梯里 10 秒）：**

> **给师范生一个"会犯错的学生"，让他上讲台之前先练十遍。**

**一句话说清和 ChatGPT 的区别：**

> **ChatGPT 是你问它答；我们是你说它挑刺。**

## 02 我们为什么做这个

### 2.1 政策层面（写材料时要引，答辩时会被问）

项目依据两份文件设计，**而且这两份文件的措辞和我们的设计是一一对应的**（这不是硬蹭）：

| 文件 | 条款 | 原文关键词 | 对应我们的什么设计 |
|---|---|---|---|
| 《教育强国建设规划纲要（2024—2035年）》 | **（二十六）促进人工智能助力教育变革** | "制定完善师生数字素养标准，**深化人工智能助推教师队伍建设**" | 整个项目的立足点：用 AI 训练教师，而不是用 AI 替代教师 |
| 同上 | **（二十八）提升教师专业素质能力** | "**提高师范教育办学质量**" | 目标用户锁定师范生 |
| 《教育部等九部门关于加快推进教育数字化的意见》（教办〔2025〕3号） | **（十一）赋能教育评价改革** | "完善结果评价，**开展多维度的过程评价、增值评价和综合评价**……开展**精准画像**" | **两轮试讲的前后指标对比 = 增值评价** |
| 同上 | **（二十二）强化人工智能安全保障** | "有效规避……**算法霸权、依赖成瘾**""坚持以人为本、**智能向善**" | **反思不代写、AI 报告交导师复核、每条结论可申诉** |
| 同上 | **（八）** | "通过智能学伴、数字导师等探索**人机协同教学新模式**" | AI 报告 + 教师复核的人机协同 |

> ⚠️ 引用时注意：通知里有时写"《关于加快推进**教育教学**数字化的意见》"，**官方正式名称是"《教育部等九部门关于加快推进教育数字化的意见》"**，别写错。

### 2.2 现实痛点（这是整个项目的出发点，务必记熟）

师范生的教学训练有一个残酷的结构性矛盾：**训练机会极少，而反馈质量极低。**

1. 一位指导教师要带几十甚至上百名师范生，**没法对每人每次试讲做全过程观察**；
2. 师范生在校期间的完整上台机会**屈指可数**；
3. 想找真实学生反复练？**成本极高、不可行、也不合伦理**；
4. 让同学扮演学生？**随机性大**——同学会本能配合你、不会真的答错、不会真的走神；
5. 试讲完得到的反馈往往是**一句话**："讲得不错""再互动一点吧"；
6. **学生最容易犯的错误无法稳定复现**——今天同学A恰好答错了，明天同学B可能答对，你练不到同一个难点；
7. 最要命的是：**师范生根本不知道自己有没有进步**，因为没有可比较的数字。

### 2.3 我们发现的"方向性偏差"（这是项目最重要的立论）

**现有 AI 教育产品，要么让 AI 当老师（替人讲课），要么让 AI 当评委（给人打分）。但研究显示，AI 恰恰最不擅长"当老师"的那一项能力——"引导"。**

有一项公开研究（SimClass，NAACL 2025，清华）用弗兰德斯互动分析（FIAS）量化对比了 AI 教师和人类教师，结果：

| 对象 | **IDR（间接引导 / 直接讲授比）** |
|---|---|
| **专家人类教师** | **1.473** |
| **新手人类教师** | **0.885** |
| **AI 教师（多智能体课堂）** | **0.058** |

> **AI 教师的 IDR 只有专家人类教师的约 1/25。**
> 翻译成人话：**AI 很会"讲"，几乎不会"引导"**（引导 = 接纳学生情绪、表扬鼓励、采纳学生想法、提问）。

**既然 AI 当不好老师，那就让它当学生。** ——这就是整个项目的转向点。

> 📌 **这句话是答辩的第一句话，务必背下来**："AI 很会讲但几乎不会引导——所以我们不讓 AI 当老师，让 AI 当那个会犯错的学生。"

## 03 要解决什么问题（传统问题 → 我们的方法 → 解决效果）

| # | 传统问题 | 我们的方法 | 解决效果 |
|---|---|---|---|
| 1 | **试讲机会太少** | AI 学生 7×24 可用，想练就练；一轮试讲约 12 分钟 | 试讲次数从"一学期 1~2 次"变成"想练多少次都行" |
| 2 | **找真实学生练成本高、不现实** | 虚拟学生全部是合成角色，零成本、零风险 | 试错成本趋近于 0；**可以放心讲错、讲砸** |
| 3 | **同学扮演学生随机性大、真实性不足** | 学生由"学生画像 + 迷思概念库 + 行为参数"共同确定 | 同一个难点可以**反复练**，每次都能遇到同类型的错误 |
| 4 | **教师指导资源有限** | 系统出**结构化报告**（编码 + 指标 + 证据链）；教师只看报告 | 教师从"逐次听课"变成"批量看报告、定位共性问题" |
| 5 | **反馈笼统（"讲得不错"）** | 反馈强制三段式：**原文证据 → 教育学解释 → 可执行动作** | 从"感觉型评价"变成"证据型评价" |
| 6 | **学生的迷思概念难以稳定复现** | **迷思概念库**（如"负负得正"的 6 种典型错误理解） | 学生不是随机胡说，而是**针对知识点精准出错** |
| 7 | **只得到笼统评价** | 用 FIAS 九类编码把每句话归类，用代码算出指标 | 评价有**公认的量表依据**，不是 AI 自由发挥 |
| 8 | **不知道自己的教学行为有没有改善** | **两轮试讲**，对比"教师纯行为指标"的变化 | 用数字回答"我到底进步了没有" |
| 9 | **难以做多轮、低成本、可量化的训练** | 训练闭环产品化：试讲→报告→反思→改教案→再讲→对比 | 形成**可持续、可累积**的训练记录与成长档案 |

## 04 核心用户

### 4.1 师范生（核心用户，一切设计围绕他）

他们可以：
- 上传教案 → 系统解析出教学目标、重难点、学情假设、**学生可能的错误**
- 进行模拟试讲，面对**不同类型的 AI 学生**
- 遇到提问、答错、质疑、走神、沉默等真实的课堂状况
- 拿到**课堂行为分析报告**（不是分数，是带证据的诊断）
- 回答系统的**反思追问**（自己写反思，系统不代写）
- 拿到**教案修订建议**（逐条确认要不要改）
- 进行**第二轮试讲**
- 查看**前后两轮的变化**（IDR、等待时间、叫答覆盖度……）

> 💡 对师范生最大的吸引力不是"AI 给了多少分"，而是**"我可以放心地讲砸，而且没人看见"**。这是产品的情感锚点。

### 4.2 指导教师

- 查看学生的试讲记录与**课堂行为指标**
- 发现全班的**共性问题**（比如"全班 20 人中 15 人的 IDR 都低于 0.3"）
- 据此设计针对性指导
- 作为教学评价的**辅助依据**（注意：是辅助，不是决定）

### 4.3 师范院校（未来设想，当前不做）

- 建立教学训练平台
- 建立师范生**教学能力档案**
- 支撑**过程性评价**与师范专业认证材料
- 扩展到更多课程与学科

> ⚠️ **给新队友的提醒**：4.3 是"未来设想"，**不要在对外的 PPT 或说明书里写得像是已经实现或已签约**。评审很容易问"哪所学校在用？"——答不上来会很难看。

## 05 产品到底怎么用（完整使用流程）

```
① 上传教案（PDF / Word）
        ↓  【教案分析】
   得到：教学目标 / 重点 / 难点 / 学情假设 / 学生可能的错误 / 教案本身的薄弱点
        ↓  【生成虚拟学生】
   得到：3~5 个差异化学生（迷思型 / 沉默走神型 / 过度积极型 / 深度质疑型）
        ↓
② 第一轮试讲（约 12 分钟，文本对话，AI 学生实时反应）
        ↓
③ 系统实时记录 → 逐句打上 FIAS 标签 → 代码计算指标
        ↓
④ 评价报告
   · 六维雷达图 + 指标卡（IDR 带"专家教师 1.473"对照刻度）
   · FIAS 九类迁移矩阵
   · 提问层次分布（布鲁姆）
   · 叫答公平性（有没有学生整节课被忽略）
   · 每条结论都可点击 → 跳回原文高亮
        ↓
⑤ 反思追问（3~5 问，**系统不代写反思，只追问**）
        ↓
⑥ 教案修订建议（结构化 patch，每条带理由，**逐条人工确认**）
        ↓
⑦ 第二轮试讲（同一份教案的修订版，学生原型保持一致，保证可比）
        ↓
⑧ 前后对比 + 成长报告
   · IDR 变化 / 等待时间变化 / 叫答覆盖度变化 / 记忆型提问占比变化
```

**关键点**：第 ④ 到 ⑧ 这一段，就是"**训练 → 反馈 → 修改 → 再训练 → 验证**"的闭环。
**如果只做到第 ④ 步（给个报告就结束），那就退化成了一个"AI 评课工具"，项目最核心的价值就没了。**

## 06 完整 Agent 架构

### 6.1 先对齐一件事：你设想的 5 个 Agent，和实际设计的 9 个是怎么对应的

你（或项目初期设想）提的是 5 个 Agent：教学任务分析 / AI 学生模拟 / 学生行为控制 / 课堂互动记录 / FIAS 分析（另加教学诊断）。
**实际设计里拆成了 9 个**，对应关系如下：

| 你的设想 | 实际 Agent | 为什么这样拆 |
|---|---|---|
| （无） | **D0 流程导演** | 原设想里没有"谁该说话"的调度者。**没有它，多个 AI 学生会抢话、重复、冷场** |
| 教学任务分析 Agent | **A1 教案分析师** | 一致 |
| AI 学生模拟 Agent | **A2 虚拟学生铸造工坊**（生成阶段）+ **A4 虚拟学生**（运行阶段） | **生成阶段和运行阶段要分开**：铸造工坊离线跑一次，虚拟学生要实时跑很多轮，提示词与输出格式完全不同 |
| 学生行为控制 Agent | **A3 场景导演** | 你提到的核心顾虑（"行为不能完全随机"）正是它的职责 |
| 课堂互动记录 Agent | **A5 教学行为编码员**（前半） | 记录与编码在我们的设计里是同一个 Agent 的两步：先记录事件流，再逐句打标签 |
| FIAS 分析 Agent | **A5 教学行为编码员**（后半，指标由代码算） | ⚠️ **拆分点**：LLM 只做"逐句分类"，**指标必须由代码计算**，不许 LLM 算 |
| （无） | **A6 教学评价员** | 把编码结果翻译成人能看懂的话 + 证据链 + 对齐矩阵 |
| （无） | **A7 反思教练** | 闭环里"反思"这一环，**只追问、不代写** |
| （无） | **A8 教案修订师** | 闭环最后一段，输出可分条确认的修订建议 |
| （无，可选） | **A9 学科教研员** | 二期做，从学科专业性挑错；**一期不做，因为它和 A6 容易打架** |

> **为什么要拆这么细？** 一条硬理由（来自源码级调研）：**如果一个 Agent 同时干"教学"和"评价"，同一个 system prompt 会自己打自己**——教学内容要求"循循善诱"，评价内容要求"冷静客观"，写在一起会互相污染。而且两者的输出格式与失败模式完全不同，混在一起会让"指标可复现"这个核心优势失效。

### 6.2 九个 Agent 的分工一览

| ID | Agent | 一句话职责 | 输入 | 输出 |
|---|---|---|---|---|
| **D0** | 流程导演 Director | 每轮决定"下一个谁说话 + 做什么动作" | 学生列表、本轮已发言、课堂进度、关键事件 | `{下一个说话人, 动作类型}` |
| **A1** | 教案分析师 | 读懂教案，并**指出教案本身的漏洞** | 教案文件 + 学科 + 学段 | 目标(ABCD)/重难点/学情假设/**迷思概念**/活动/评价/**设计薄弱点** |
| **A2** | 虚拟学生铸造工坊 | 造出 3~5 个有教育意义的差异化学生 | A1 输出 + 难度档位 | 学生画像（含迷思概念、参与度、语言约束、认知状态） |
| **A3** | 场景导演 | 控制节奏 + 注入关键事件（走神/沉默/超纲/坚持错误） | 课堂状态 + 事件牌库 | 事件触发指令 |
| **A4** | 虚拟学生 ×N | 以学生身份实时说话，并**回写认知状态** | 画像 + 状态 + 课堂历史 + 同伴已发言 | 台词 + 行为 + 状态变化 |
| **A5** | 教学行为编码员 | 逐句打 FIAS 标签；**指标由代码算** | 事件流 + 教案结构 | 标签序列 + 指标 + 等待时间 + 叫答分布 |
| **A6** | 教学评价员 | 把指标翻译成人话，每条挂证据 | A5 输出 + 教案结构 | 评分 + 证据链 + 对齐矩阵 + 风险提示 |
| **A7** | 反思教练 | 只追问，**不写反思** | A6 输出 + 关键失败片段 | 3~5 个递进追问 |
| **A8** | 教案修订师 | 输出可分条确认的修订建议 | 评价 + 反思 | 结构化修订补丁（含理由与依据） |
| **A9** | 学科教研员（二期） | 从学科专业性挑错 | 教案 + 试讲 | 学科层面的问题清单 |

### 6.3 三条让系统"可信"的架构纪律（**这是本项目技术含量的核心**）

1. **LLM 只做分类，指标由代码算。**
   LLM 负责判断"这句话属于 FIAS 第几类"，但 **TT/ST/IDR/SIR 的分子分母、等待时间、叫答次数，全部由 Python 代码计算**。这样同一份对话重复计算的结果**完全一致**，可以复现、可以审计。
2. **事件流只追加不修改，指标可随时重算。**
   数据库里存的是"第 42 秒，教师说了一句话，属于第 6 类"这样的**原始事件**；指标是从事件流算出来的**派生数据**。评委问"这个分数怎么来的"，我们能一步步重算给他看。
3. **LLM 只选人，代码兜底。**
   D0 导演让 LLM 决定"下一个谁说话"，但返回的人名**必须**在候选名单里，否则由代码按优先级选一个。**永远不让 LLM 的输出直接决定流程。**

## 07 AI 学生到底是什么

### 7.1 它不是一个聊天机器人，它是一组参数的集合

一个 AI 学生的完整定义包含 **6 个维度**：

```yaml
id: S1
name: 小林
archetype: 迷思型                 # ① 原型
prior_knowledge: 会用公式但不懂算理   # ② 学习基础
misconception: M-01               # ③ 迷思概念（指向知识库）
personality: 安静、怕答错、被点名会紧张  # ④ 人格特征
engagement_base: 0.5              # ⑤ 行为参数（0~1 参与度基线）
language_profile:                 # ⑥ 语言约束（防止说话像老师）
  grade_band: 初中
  max_sentence_len: 18
  forbidden_words: [认知负荷, 维度, 本质属性]
state:                            # ⑦ 运行中的认知状态（关键！）
  understanding: 0.2
  confusion: 0.7
  emotion: 焦虑
  convinced: false
```

### 7.2 四类原型（每类都有明确的教育训练目的）

| 原型 | 训练师范生什么能力 | 行为特征 |
|---|---|---|
| **迷思型** | **诊断能力**——从错误回答反推学生的认知结构 | 坚定地给出错误答案，并用错误逻辑解释；**被追问后至少坚持一轮** |
| **沉默 / 走神型** | **课堂管理能力 + 教育公平意识** | 不主动发言、被点名才回神、会走神（触发关键事件） |
| **过度积极型** | **节奏控制能力** | 抢答、跑题、占用课堂时间 |
| **深度质疑型** | **学科深度** | 提超纲问题、追问"为什么" |

> 💡 **设计时的自我提醒**：不要做"6 个花哨的学生"，**做 3 个差异明确、能被评委一眼记住的学生**。数量不是卖点，"每种学生的存在都有教育目的"才是。

### 7.3 "负负得正"课时的学生台词示例（Demo 就要用这个）

| 学生 | 典型台词 |
|---|---|
| 小林（迷思型） | "老师说的，两个负号就变正号，背下来就行了嘛。"<br>"可是……为什么两个负数乘起来一定是正数呀？"<br>（被追问后）"我还是觉得就是规定，记住就好。" |
| 小周（沉默走神型） | （长时间不发言）<br>（被点名）"啊？……老师你刚说什么？" |
| 阿豪（过度积极型） | "那如果是负数乘分数呢？"<br>"我知道我知道！等于正数！"（其实没想明白） |

### 7.4 语言约束为什么重要（这是有文献依据的）

一项教师访谈研究（BEA 2025）指出，现有 LLM 模拟学生有**五类真实性缺陷**：
1. 真实性不足 2. **语言复杂度过高**（说话像老师）3. 缺乏情绪 4. **不自然地专注**（永远在听、永远配合）5. **逻辑不一致**（前后矛盾）

> 🎯 **这五条就是我们的验收清单**，而且每一条都能在 Demo 里当场演示"我们解决了"：
> - 语言复杂度 → `language_profile` 限制句长与禁用词
> - 不自然专注 → 走神/沉默由**代码触发**
> - 逻辑不一致 → **认知状态机**："我前面答错了，所以我现在还是不懂"
> - 缺乏情绪 → 有焦虑/兴奋状态并影响发言
> - 真实性 → 错误来自**迷思概念库**，不是随机胡说

## 08 FIAS 为什么重要

### 8.1 FIAS 是什么

**FIAS = Flanders Interaction Analysis System（弗兰德斯互动分析系统）**，是教育学界用了几十年的**课堂话语分析工具**。它的思想很简单：

> **把课堂上每一句话归到一个类别，然后看这些类别怎么分布、怎么交替——就能看出这节课是"老师灌"还是"学生想"。**

### 8.2 九个类别（这是必须背下来的表）

| 编码 | 类别 | 中文名 | 例子 |
|---|---|---|---|
| **1** | 教师·**间接影响** | 接受情感 | "看得出这道题让你有点挫败，没关系" |
| **2** | 教师·间接影响 | 表扬鼓励 | "很好！思路很清楚" |
| **3** | 教师·间接影响 | 采纳想法 | "你刚说'先看符号'，我们就按你的思路来" |
| **4** | 教师·间接影响 | 提问 | "谁能说说为什么？""小林，你试试" |
| **5** | 教师·**直接影响** | 讲授 | "负负得正的意思是……" |
| **6** | 教师·直接影响 | 给出指令 | "把书翻到第 30 页""大家记住，考试要考" |
| **7** | 教师·直接影响 | 批评 | "这么简单都不会？" |
| **8** | 学生 | 应答 | 被提问后作答 |
| **9** | 学生 | **主动发起** | 未被提问而自发提问、质疑 |

**记住这个分块**：**1~4 是"引导"，5~7 是"灌输"，8~9 是学生。**

### 8.3 四个指标（公式必须由代码算）

| 指标 | 公式 | 含义 |
|---|---|---|
| **TT** | (第 1~7 类计数) ÷ 总计数 | 教师话语占比 |
| **ST** | (第 8~9 类计数) ÷ 总计数 | 学生话语占比 |
| **IDR** | **(第 1~4 类计数) ÷ (第 5~7 类计数)** | 🔥 **间接引导 / 直接讲授** |
| **SIR** | 第 9 类 ÷ (第 8 类 + 第 9 类) | 学生主动发起比例 |

### 8.4 ⚠️ 科学性边界：四个指标里只有 IDR 能代表教师能力

**这是本项目最重要的一条科学纪律，也是答辩时最能加分（或最容易翻车）的地方。**

| 指标 | 能代表师范生的教学能力吗？ | 为什么 |
|---|---|---|
| **IDR** | ✅ **能，而且只有它最干净** | 它在**教师自己的话语内部**做分子分母（1~4 类 ÷ 5~7 类），**与"学生说了多少话"完全无关**。它只回答一个问题：**这位老师在自己开口时，选择"引导"还是"灌输"？** |
| 等待时间 / 抢答率 | ✅ 能 | 完全由教师行为决定（问完等多久） |
| 记忆型提问占比 | ✅ 能 | 完全由教师的提问设计决定 |
| 叫答覆盖度 / 被忽略学生数 | ✅ 能 | 完全由教师的点名行为决定 |
| **TT / ST** | ⚠️ **只能算部分** | 学生说了多少，很大程度取决于**我们把 AI 学生设定得多爱说话** |
| **SIR** | ❌ **基本不能** | 在我们的系统里"学生"是 AI，**主动发起比例是我们设计出来的参数**（参与度设 0.3 还是 0.8 由我们决定）。把它当成师范生能力，是**逻辑错误** |

**由此得出的三条使用纪律：**
1. **成效验证只能用"教师纯行为指标"**：IDR + 等待时间 + 抢答率 + 记忆型提问占比 + 叫答覆盖度 + 被忽略学生数。
2. **TT / ST / SIR 只作"课堂情境描述"**（如"这节课教师话语占比 78%，学生发言集中在两位"），**不得作为"能力提升"的证据**。
3. **两轮试讲必须用相同的学生原型与参与度配置**，否则 TT/ST 的变化无法解释。

### 8.5 顺带解释一个容易误读的数字

SimClass 论文里 AI 课堂的 **SIR = 0.896**，远高于专家人类教师的 0.121。
**看起来好像"AI 的学生比真人学生更主动"——但那是因为 AI 学生的主动发言是设计出来的，不代表教学更成功。**
**引用这个数字时务必说明这一点**，否则懂行的评委会认为我们没读懂文献。

### 8.6 为什么 FIAS 是本项目的"护城河"

**因为我们查证过：把 FIAS 做成可自动运行的服务，目前是空缺的。**
论文里大量使用 FIAS，但**其公开实现代码里连一行 FIAS 编码都没有，只有一张名叫 `FIAS.png` 的图片**。

> 📌 **答辩金句**："我们测的是 **IDR**——因为它只跟老师自己有关。"

## 09 迷思概念库

### 9.1 是什么

一本"**学生在某个知识点上最可能怎么错**"的清单。

### 9.2 为什么必须有它（这是"反事实学生"能成立的地基）

**如果没有这个库**，AI 学生只能随机犯错 → **教学训练价值很低**（随机错误练不出诊断能力，而且可能出错在一个毫无教学意义的点上）。

**有了这个库**，AI 学生就能：
- 主动模拟**真实学生在这个知识点上最典型的错误**
- 每次练同一个难点时，**都能稳定遇到同类型的错误**
- 让教师面对"**我讲过一遍了他还是不懂**"的真实困境

> **一句话说清它的价值**：它把系统从 **"AI 陪你聊天"** 升级为 **"AI 针对教学难点模拟学生"**。

### 9.3 "负负得正"的 6 种典型迷思（Demo 专用，需学科教师审阅）

| id | 迷思概念 | 学生典型说法 | 暴露它的提问 |
|---|---|---|---|
| **M-01a** | **把负号理解为"简单消失"** | "负号乘负号就自动消失了呀" | "两个负号为什么会消失？用一个具体例子说明给我听。" |
| **M-01b** | **认为"负负得正"只是一条规定** | "书上就是这么规定的，记住就行。" | "如果是规定，那为什么会这样规定？能不能从数轴看出来？" |
| **M-01c** | **无法从数轴理解** | "数轴上负数在左边，两个左边怎么变成右边了？" | "在数轴上，乘以 -1 相当于什么操作？" |
| **M-01d** | **无法理解规律模式** | "（-3）×（-2）为什么不是 -6？" | "看看这串式子：3×(-2)=-6，2×(-2)=-4，1×(-2)=-2，0×(-2)=0，那 (-1)×(-2)=？你发现了什么规律？" |
| **M-01e** | **混淆减法与负数** | "减号和负号不是一回事吗？" | "3-(-2) 和 3+(-2)，结果一样吗？" |
| **M-01f** | **混淆乘号与正负号** | "符号太多了，我分不清哪个是运算、哪个是正负" | "这个式子里有几个运算符？分别是什么？" |

> ⚠️ **两条待办**：① 这 6 条**必须由数学教育方向的教师审阅**后才能正式使用；② 每条都要写进知识库的 YAML 格式，含 `resistance`（被追问后仍坚持的轮数）。

### 9.4 库里目前还有什么

除"负负得正"外，初稿已整理 **20 条**初中数学迷思概念，覆盖：有理数运算（绝对值、负数比大小、减法大减小、运算顺序、异号相加）、代数式与方程（合并同类项指数相加、去括号符号、移项不变号、方程与恒等式、分式方程增根、因式分解不彻底）、函数与图像（函数=公式、k 的意义、相似比与面积比）、几何统计概率（π 当精确值、忽略等可能前提、平均数代表全体、全等与相似、三角形外角）。

**这些是"迁移到其他知识点"的储备**，Demo 只用"负负得正"那一组。

> ⚠️ **诚实声明**：这批迷思概念是**依据课程标准与学科教学知识整理的经验归纳**，**不是**来自真实学生访谈的语料。如果之后能补上真实学生原话，可信度会显著提升。

## 10 两轮试讲闭环

### 10.1 闭环长什么样

```
第一轮试讲 → 编码 → 报告 → 反思 → 改教案 → 第二轮试讲 → 对比
```

### 10.2 为什么"两轮"是项目的命门

**因为只做一轮 = 只做了一个"AI 评课工具"。** 而"AI 评课"这条路**已经被走透了**——有师范院校的同类系统已经服务上千名师范生、完成近 2000 次测评，还与多位学科专家的独立评分做过一致性验证。

> **所以我们的差异不在"能评课"，而在"能证明改进了"。**
> **两轮之间的"教师纯行为指标变化"，就是我们唯一无可替代的证据。**

### 10.3 三个必须遵守的实验控制（否则数据不可比）

1. **同一份教案**：第一轮与第二轮必须用同一课时，第二轮基于第一轮的修订版；
2. **学生配置一致**：两轮生成的学生**原型相同**（迷思型 + 沉默型 + 过度积极型各一）；
3. **第一轮不提前显示指标**：防止师范生"为了指标而表演"。

### 10.4 报告上要显示的对比项（Demo 用这一组数字）

| 指标 | 第一轮 | 第二轮 | 方向 |
|---|---|---|---|
| **IDR** | 0.12 | **0.58** | ↑ |
| 平均等待时间 | 1.1 秒 | **3.4 秒** | ↑（目标 ≥3 秒） |
| 被忽略学生数 | 1 人 | **0 人** | ↓ |
| 记忆型提问占比 | 5/6 | **2/7** | ↓ |

> ⚠️ **上面这组数字是"Demo 演示用的示例值"，不是真实测试结果。** 真实数据必须通过**配套的《用户测试与成效验证方案》**（同目录 `08_用户测试与成效验证方案.md`）采集，**绝不能把示例值写进说明书当成效**。

### 11.2 各部件的位置与职责

| 部件 | 位置 | 职责 | 备注 |
|---|---|---|---|
| **前端** | 最上层 | 试讲交互、实时反馈、报告可视化 | 与用户直接接触的唯一一层 |
| **后端** | 中间 | 接口、会话管理、文件解析、导出 | FastAPI |
| **编排层** | 核心 | 三张状态图，控制 Agent 之间的流转 | LangGraph |
| **LLM** | 模型层 | 理解自然语言、模拟学生、生成追问、解释问题 | **可插拔**，不绑定某一家 |
| **规则引擎 / 代码** | 贯穿 | 指标计算、统计、对比、事件触发、校验 | **可信度的来源** |
| **知识库** | 知识层 | 迷思概念、语言画像、编码规则、评价量规 | MVP 用 YAML/JSON 文件即可 |
| **RAG** | 知识层 | 检索教案原文，供 Agent 引用 | ⚠️ **MVP 不是必需**，见 11.6 |
| **数据库** | 数据层 | 事件流 + 派生指标 + 报告 + 迭代记录 | SQLite 足够 |

### 11.3 ⭐ 什么交给 LLM，什么交给代码（本项目最关键的工程判断）

> **一句话原则：不要把所有东西都交给 LLM。**

| ✅ 交给 LLM | ❌ 绝不交给 LLM（必须由代码/规则做） |
|---|---|
| 理解自然语言（教案、教师话语） | **FIAS 指标计算**（TT/ST/IDR/SIR 的分子分母） |
| 扮演 AI 学生、生成台词 | **等待时间 / 抢答率 / 叫答次数的统计** |
| 生成追问 | **两轮数据对比** |
| 解释教学问题的含义 | **关键事件的触发时机** |
| 判断"这句话属于 FIAS 第几类"（**只做分类**） | **导演选人的合法性校验** |
| 生成教案修订建议的措辞 | **数据保存与结构校验** |

**为什么这条这么重要？** 举一个具体例子：

> 如果我们让 LLM"读完对话然后给出 IDR 数值"，那么**同一份对话问两次可能得到两个不同的数字**——这个系统的评价就彻底不可信了。
> 如果让 LLM 只做"第 42 秒这句话属于第 6 类"这样的单句判断，再由代码去数：**那么指标永远一致、可复现、可审计**。
> **LLM 会犯错，但我们把它的错误限制在"单句分类"这一层，而它犯错也不会让指标变成随机的。**

### 11.4 技术选型与理由

| 层 | 选择 | 为什么选它（对比后） |
|---|---|---|
| 前端 | Next.js + TypeScript + Tailwind | 生态成熟，图表用 ECharts；与主流教学智能体项目同栈 |
| 后端 | **FastAPI（Python）** | Agent 编排生态在 Python；教案解析（pypdf）也在 Python。**不建议用前端框架的 API 路由写 Agent**，后期会很痛苦 |
| 编排 | **LangGraph** | 状态图 + 可中断 + 可恢复，正好对应"备课→试讲→编码→评价→反思→修订"的流转 |
| 数据库 | **SQLite**（需要再换 Postgres） | 比赛规模完全够用。**不要一上来上 MongoDB + RabbitMQ**——那是有几十个常驻进程的项目才需要的 |
| 模型 | **可插拔 + 分阶段路由** | 学生发言要快（用轻量模型），评价与教案修订要准（用强模型）；不绑定一家厂商 |
| 检索 | **MVP 用词法检索 / 整篇入上下文** | 见 11.6 |
| 流式 | **SSE** | AI 学生的话必须逐字蹦出来才有"活人感" |
| 部署 | 本机 + 一个可公开访问的临时部署 | 比赛通常要求"可访问地址或源码" |

### 11.5 数据怎么存（MVP 最小表集）

```sql
lesson          教案（学科/学段/课时/原文件）
lesson_version  教案版本（v1/v2，v2 由 patch 应用生成）
session         一次试讲（关联教案版本、轮次）
turn            ★事件流：谁、第几秒、说了什么、FIAS第几类、等待多久
event           ★事件：走神/沉默/超纲/坚持错误
metric          ★派生指标：TT/ST/IDR/SIR/提问层次/等待时间/叫答分布
report          评价报告（评分/证据/对齐矩阵/风险提示）
reflection      反思（追问清单 + **师范生自己写的文本**）
patch           教案修订建议（含理由、证据、是否被接受）
student_profile 虚拟学生画像与认知状态
```

**★ 是这个架构最重要的一句话**：带 ★ 的三张表里，`turn`/`event` 是**只追加不修改的原始记录**，`metric` 是**可以从原始记录重算出来的派生数据**。
**这就是"可审计"的全部秘密**——评委问"这个分数怎么来的"，我们能从第一句话开始重算给他看。

### 11.6 一个重要的技术判断：为什么 MVP **不上向量库**

很多同学一提到"教育 AI"就想到"必须上向量数据库 + RAG"。**我们判断 MVP 不需要**，理由：

1. **数据量极小**：一份教案通常几千字，**完全可以整篇塞进模型的上下文**，检索反而增加了出错环节；
2. **有先例**：我们重点调研的那个上万星的开源多智能体课堂项目（OpenMAIC，MIT），其 RAG 默认实现用的是**内存词法索引，而不是向量库**；
3. **少一个组件就少一类故障**：向量库涉及嵌入模型、维度、索引、检索召回率——每一个都是 Demo 现场翻车的风险点；
4. **二期再上不迟**：当"多课时、多学科、跨学期"的历史数据积累起来后，再引入向量检索是自然的。

> 📌 **这是可以在答辩中主动讲出来的判断**：它显示我们不是"见什么热就上什么"，而是**按数据规模做技术取舍**。

## 12 项目创新点

> ⚠️ **先看这一节末尾的"诚实边界"**。创新点的表述**必须收敛**——如果评委读过文献而我们过度声称"没人做过"，那是致命伤。

### 创新 1：AI 学生不是聊天机器人，而是"参数化的学生"

它具有：**学段 / 学科 / 学习基础 / 人格特征 / 迷思概念 / 行为参数 / 认知状态**七个维度。
因此可以稳定地模拟**不同类型的、以及同一个类型在不同知识点上的**学生。

### 创新 2：从"生成反馈"升级到"课堂行为分析"

不是告诉用户"你的教学很好"，而是：**把每一句话归类 → 用代码算出指标 → 定位到具体行为**。

### 创新 3：FIAS + LLM

让大模型的自然语言理解能力，与**经典课堂互动分析方法**结合。
**LLM 负责"这句话是什么"，FIAS 负责"这意味着什么"。**

### 创新 4：两轮试讲构成的训练闭环

> 第一次 → 反馈 → 修改 → 第二次 → 对比

**不是只评价一次，而是证明"改进了"。** 这是本项目区别于所有"AI 评课工具"的核心。

### 创新 5：可解释、可追溯的反馈

反馈尽可能追溯到**具体课堂行为**，而不是完全由大模型主观生成。
落地形式：**每条结论都挂原文证据锚点，点击即高亮原句**。

### 创新 6（补充）：只针对"教师本身"的指标纪律

我们明确区分了"**教师纯行为指标**"（IDR、等待时间、叫答覆盖度）与"**受 AI 参数影响的指标**"（TT/ST/SIR），**只用前者作为成效证据**。
——**这条纪律本身就是学术严谨性的体现**，很多同类项目会在这里出错。

### 创新 7（补充）："教案—实施—评价"建构一致性对齐矩阵

不只评"讲得好不好"，而是检查：**教案写的目标 ↔ 实际发生的行为 ↔ 评价手段，三者对不对齐**。
输出四色矩阵：**对齐 / 目标落空 / 游离活动 / 不可评目标**。
> 师范生最常犯、却最少被检测的错误，就是"写了目标但没教到""教了但和目标无关""有目标却没任何检测手段"。

---

### ⚠️ 诚实边界（写材料前必须知道，避免翻车）

| 创新点 | 有没有先例？ | 我们应该怎么说 |
|---|---|---|
| AI 扮演"带迷思概念的学生" | **有**。已有研究（Student GPT / Student ChatGPT，*IJAIED* 2025）用聊天机器人扮演"比例推理有迷思概念的初中生" | ❌ 不能说"我们首创让 AI 犯错"<br>✅ 应说："**该机制已被单点验证；但把它做成'反事实学生 → FIAS 行为量化 → 反思 → 教案迭代'的师范生训练闭环，尚无公开工作。**" |
| AI 评课 / 师范生教学测评 | **有，而且做得很成熟**。有师范院校的同类系统已服务 1000+ 师范生、近 2000 次测评、与多位学科专家独立评分做过一致性验证，并入选省级优秀案例 | ❌ 不能说"我们做 AI 评课是创新"<br>✅ 应说："**我们不做重复的'AI 打分'；我们的差异在两轮闭环与可审计的证据链。**" |
| **FIAS 自动编码** | **没有查到公开实现**。论文大量使用 FIAS，但其公开代码里**只有一张 FIAS 图片、零编码代码** | ✅ 这是我们**最硬的一个创新点**，可以正面主张 |
| 两轮试讲闭环 + 前后对比 | 在设计上少见（同类工作多为单次评价） | ✅ 可以主张，但要强调"闭环"而非"两轮"这个形式 |
| 建构一致性对齐矩阵 | 未被做成结构化诊断矩阵 | ✅ 可以主张 |

> 📌 **给新队友的一句话**：**这个项目最大的风险不是"技术做不出来"，而是"把话说得太满"。** 说"我们做了全世界没人做过的事"，一定被问倒；说"我们把已经验证过的机制，第一次接成了完整的训练闭环"，站得住。

## 13 为什么可行

### 13.1 逐部件可行性

| 要做的事 | 靠什么实现 | 成熟度 |
|---|---|---|
| 理解教师与学生的对话 | LLM 的自然语言理解 | ✅ 成熟，这是 LLM 最擅长的事 |
| 承担不同角色（导演/学生/评价员） | Agent + 独立 system prompt | ✅ 成熟，多角色是 LLM 的强项 |
| 让 AI 学生像学生 | 学生画像 + 语言约束 + 提示词 | ⚠️ **中等难度**，是主要攻关点 |
| 加载教学知识 | YAML/JSON 知识库（迷思概念、量规） | ✅ 简单可靠，人可读可改 |
| 课堂行为编码 | LLM 逐句分类 + 规则卡约束 | ⚠️ **需要验证准确率** |
| 指标计算 | **Python 代码** | ✅ 非常简单（就是数数和除法） |
| 记录试讲过程 | 数据库事件流 | ✅ 成熟 |
| 展示课堂过程与结果 | 前端 + 图表库 | ✅ 成熟，工作量在"做得好不好看" |
| 两轮对比 | 代码读取两轮 metric 做差 | ✅ 非常简单 |

### 13.2 一句话总结可行性

> **这个项目之所以可行，是因为"最不靠谱的部分（自然语言理解与角色扮演）交给最擅长它的 LLM，而"最需要可靠的部分（指标、统计、对比）交给最不会出错的代码"。**

**我们不是在赌 LLM 不犯错，而是在设计上让它犯错也不影响结论。**

### 13.3 几个"降低风险"的具体设计

1. **指标不由 LLM 计算** → 评价结论永远一致；
2. **结构化输出 + Schema 校验 + 重试 + 降级** → LLM 输出格式错了，系统不会崩（叙事照常展示，只是结构化数据不落库）；
3. **关键事件由代码触发** → Demo 不会"该走神时不走神"；
4. **导演选人由代码兜底** → 不会出现"导演连续叫同一个人"或"叫了一个不存在的人"；
5. **预跑数据可一键回放** → 现场网络出问题时立刻切换；
6. **不做语音与数字人** → 砍掉最大的两类不确定因素。

## 14 真正的技术难点

> **先说结论**：调用 LLM API 不是难点。**真正的难点是"让不可控的东西变得可控"。**

### 难点 1：AI 学生的真实性——怎么让它像学生，而不像老师？

**问题表现**：AI 学生一张口就是"从数学本质上看，负负得正体现了……"，**它讲得比老师还好**，训练价值立刻归零。

**应对**：
- `language_profile` 硬约束（句长上限、禁用学术词表）；
- prompt 里写死"你就是个 13 岁的学生，你不懂教学法，不要总结，不要替老师补充"；
- **错误必须来自迷思概念库**，不许自由发挥。

**难度评级**：⭐⭐⭐⭐（最需要反复调的一项）

### 难点 2：学生行为的可控性——不要一直说，也不要一直不说

**问题表现**：不做控制时，AI 学生会**抢着说话**（每轮都发言）或者**一直沉默**（模型倾向于"礼貌地等待"）。也可能每次都犯同一个错，或者突然说出大学水平的知识。

**应对**：
- **参与度参数** + 代码控制的"允许发言"闸门（不是每轮都让所有人有资格说话）；
- **关键事件由代码触发**（走神/沉默不是"LLM 自己决定"）；
- 迷思概念的选取带随机性，但**受控于知识点**；
- **认知状态机**保证"他会的还是会的，不会的还是不会的"。

**难度评级**：⭐⭐⭐⭐

### 难点 3：FIAS 自动编码的准确性

**问题表现**：LLM 判断"这句话属于第几类"会出错，典型分歧：
- "大家记住，考试要考" → 是 **5 讲授** 还是 **6 指令**？（**正确答案是 6**）
- "很好！那谁能说说为什么？" → 表扬(2) 还是 提问(4)？（**按主导意图记 4，备注保留表扬**）
- 教师自问自答 → 只记 4，且**不产生 8/9 类**，同时计入"抢答率"

**应对（五道防线）**：
1. **规则卡**：把易混边界写成硬规则放进 prompt；
2. **单句分类**：一次只判一句，不让它通读后总结（降低出错面）；
3. **Schema 约束**：输出必须是 `{句子序号, 类别编号}` 的固定格式；
4. **校验**：类别编号必须在 1~9 之间，否则重试；
5. **人工抽查**：随机抽 20~30 条请学科教师独立标注，**在不看 AI 结果的前提下**比对一致率。

**难度评级**：⭐⭐⭐（技术不难，**难在"证明它准"**）

### 难点 4：评价的科学性——尤其是"SIR 到底代表什么"

**这是本项目最容易被专业评委击穿的地方。**
如果我们在报告里写"SIR 提升 → 教学能力提升"，**懂 FIAS 的评委一句话就能问倒**。

**应对**：**把这条边界写进产品本身**——报告里把指标分成两组：
- 「**教师行为指标**」（用于判断改进）：IDR、等待时间、抢答率、提问层次、叫答覆盖度
- 「**课堂情境指标**」（仅用于描述）：TT、ST、SIR

**难度评级**：⭐⭐（技术无难度，**是认知与纪律问题**）

### 难点 5：防止"AI 自娱自乐"

**问题表现**：AI 生成一屏漂亮的分析文字，读起来很有道理，**但可能没有任何教学价值**，甚至是错的。这是所有 LLM 应用的通病。

**应对**：
- 每条结论**必须有证据**（无证据不出结论）；
- 用量规约束，不用自由发挥；
- **必须做真实用户测试**（n≥10，两轮试讲），用行为数据验证；
- 人工编码一致性校验。

**难度评级**：⭐⭐⭐⭐（**这是"项目到底有没有价值"的分水岭**）

### 难点 6：教学反馈不能变成空话

**❌ 不能出现的反馈**："你可以更加关注学生。""课堂氛围可以更活跃。"

**✅ 应该出现的反馈**：
> "在第 3 次学生表达困惑后（第 7 分钟），你直接进行了概念解释，**没有进一步追问学生原有理解**。下一轮可以先追问'你为什么认为负负得正就是规定？'，再进行解释。"
> —— 依据：FIAS 第 5 类（讲授）连续出现 4 次，期间无第 4 类（提问）与第 3 类（采纳想法）。

**应对**：反馈强制三段式——**原文证据 → 教育学解释 → 可执行动作**；任何不含证据的结论在生成阶段就被判为不合格。

**难度评级**：⭐⭐⭐

### 难点 7：数据隐私与伦理

**要考虑的**：教案与试讲记录（属于教师的创作与个人数据）、对话记录存储、AI 依赖导致的教师能力退化、算法偏差、AI 评价不能替代教师最终判断。

**应对**：见第 15 节。

**难度评级**：⭐⭐（技术不难，**但一票否决——漏了会直接扣掉"合规与伦理"的 15 分**）

### 14.1 难度总排序（供排期参考）

| 排序 | 难点 | 谁最适合负责 |
|---|---|---|
| 1 | AI 学生真实性与行为可控（难点 1+2） | Agent 方向的同学，**需要反复调，最耗时间** |
| 2 | 防止 AI 自娱自乐 / 真实验证（难点 5） | 测试方向的同学 + 队长 |
| 3 | 反馈不能是空话（难点 6） | 评价 Agent 的同学 |
| 4 | FIAS 编码准确性（难点 3） | 数据方向的同学 |
| 5 | 评价科学性边界（难点 4） | **队长必须亲自把关** |
| 6 | 隐私与伦理（难点 7） | 写材料/答辩的同学 |

## 15 项目边界与伦理

### 15.1 我们**不是**什么（这一段要能背下来）

| ❌ 我们不是 | 为什么（不是谦虚，是设计原则） |
|---|---|
| ❌ **AI 自动给教师打分** | 评价只描述**具体教学行为及其教育依据**，不出具"教师能力结论" |
| ❌ **AI 替代指导教师** | 研究显示 AI 反馈在"可信度与有用性"上**显著低于**人类教师反馈。所以我们的定位是"**人类导师之前的预训练场**"，AI 报告交导师复核 |
| ❌ **AI 自动决定教师是否合格** | 涉及资格判断就是考核性评价，伦理与法律风险都不可承受 |
| ❌ **AI 自动写完整教学反思让学生直接提交** | **这是刻意的**——反思环节不提供"AI 帮我写"按钮，只做追问。AI 代劳会让师范生的反思能力退化 |
| ❌ **用一个指标证明教学能力提升** | 只用"教师纯行为指标"且只作**过程性/增值性**证据，不作能力结论 |

### 15.2 我们**是**什么

| ✅ 我们是 |
|---|
| ✅ **教学训练辅助工具**（把试错成本降到接近 0） |
| ✅ **AI 学生模拟器**（可配置、可复现、有迷思概念依据） |
| ✅ **课堂互动分析工具**（FIAS 编码 + 代码算指标） |
| ✅ **教学反思辅助工具**（只追问，不代写） |
| ✅ **多轮训练平台**（两轮对比 + 成长记录） |

> **最终判断仍然由教师 / 指导教师 / 学生自己完成。**

### 15.3 伦理与合规的具体设计（直接对应评分里 15 分的"合规与伦理"）

| 风险 | 我们的对策 |
|---|---|
| **数据安全与隐私** | ① **最小采集**：只采集师范生**主动上传**的教案与文本试讲记录；② **不采集任何影像、音频、人脸、眼神、行为轨迹数据**（这是刻意放弃，也是与依赖摄像头的同类系统最大的合规差异）；③ 提供数据查看与**删除**入口；④ 未经本人书面授权不用于任何公开展示 |
| **不涉及真实未成年人数据** | 虚拟学生全部为合成角色，不使用任何真实学生数据，不生成对真实学生的评价 |
| **算法公平** | 所有评分维度、公式、阈值**在系统内公开可查**；**不设黑箱** |
| **教师权益** | 每条结论**可点击回溯原文证据**，教师**可对结论提出异议**；不出具能力结论 |
| **防止依赖成瘾** | 反思路径**不提供代写**；教案修订**必须人工逐条确认**；系统定位为训练场而非代笔者 |
| **生成内容标注** | 所有 AI 生成内容标注来源与生成时间 |
| **知识产权** | 参考的开源项目（MIT / Apache-2.0）均保留版权与许可声明并在代码仓库列明；**主动披露**参考了什么、哪些是自研（隐瞒 = 学术不端风险） |
| **知情同意** | 用户测试前提供知情同意书（数据范围、用途、保存期限、随时退出与删除的权利），访谈录音单独授权 |
| **未成年被试** | **本方案不涉及**——被试均为成年在校师范生 |

## 16 评委可能怎么质疑（22 问，含陷阱题）

> **用法**：答辩前两人一组互相问，一人问一人答，**答不上来的打标记，重点练标记的**。
> **核心心法**：**主动承认边界比强辩更得分。** 评委问这些不是为了难倒你，而是想看"你知不知道自己的边界在哪"。

### Q1 为什么不用 ChatGPT？

- **评委为什么问**：这是最常见的"你凭什么存在"问题。他们怀疑你只是套了个壳。
- **推荐回答思路**：三点，按"方向 → 标准 → 状态"递进。
  1. **角色方向相反**：ChatGPT 是你问它答；我们是**你说它挑刺**——它扮演的是立场与你相对的学生。
  2. **评价有锚**：ChatGPT 的反馈是自由文本，同一节课问两次得到不同评语，**不可比较、不可复现**；我们的评价锚定 **FIAS 九类编码**，指标由代码计算，**可复现、可审计**。
  3. **有状态、有闭环**：ChatGPT 没有课堂事件流，翻篇即失忆；我们记录每一轮，能做出**两轮对比**和成长曲线。
- **不应该说什么**：
  - ❌ "我们的提示词写得更好/更专业"（这不是壁垒）
  - ❌ "我们用了更先进的模型"（更不是壁垒）
- **继续追问怎么办**："你能不能用 ChatGPT 加上一段提示词做出来？"
  → 回答："**能做出对话，但做不出可审计的指标和两轮对比。** 因为 IDR 这类指标必须是代码从结构化事件流里算出来的；如果让模型自己读对话然后报一个数字，同一份对话两次结果可能不同，那这个评价就不能用了。"

### Q2 你们和普通 AI 对话产品有什么区别？

- **评委为什么问**：同上，但更泛，想看产品层面的差异。
- **推荐回答思路**：用"六个有"回答：**有标准（FIAS）、有状态（事件流）、有闭环（两轮）、有证据（可点回原文）、有产物（报告/反思/教案 v2 可归档）、有边界（不做影像、不代写反思）。**
- **不应该说什么**：❌ 长篇描述功能列表（会显得没重点）
- **继续追问怎么办**："那你这个和一个打分系统有什么区别？"
  → 回答："打分系统只给结论，我们给**证据链**——每条结论都能点回到那句原话。而且我们不给出'教师能力结论'，只描述具体行为。"

### Q3 AI 学生真的像学生吗？

- **评委为什么问**：这是最关键的一问。他们见过太多"AI 一开口就像教授"的演示。
- **推荐回答思路**：**直接承认这是公开承认的行业难题，然后展示我们打在了点上。**
  1. 先给证据：有研究通过教师访谈总结了 LLM 模拟学生的**五类真实性缺陷**——真实性不足、**语言复杂度过高**、缺乏情绪、**不自然地专注**、**逻辑不一致**。
  2. 再说我们的四条对症措施：语言约束（句长/禁用词）→ 治语言复杂度；走神沉默由**代码触发** → 治"不自然专注"；**认知状态机**（答错后不会自己变聪明）→ 治逻辑不一致；情绪状态影响发言 → 治缺乏情绪。
  3. **最好的收尾是现场演示**："我现在可以让小林答错，并且坚持不改——请看。"
- **不应该说什么**：❌ "我们的 AI 学生非常真实"（空口无凭，且一定被追问）
- **继续追问怎么办**："你怎么量化它的真实性？"
  → 诚实的回答："**目前我们还没有量化的真实性指标，这是下一步工作。** 我们计划的做法是让学科教师对随机抽取的学生发言做盲评（'这句话像不像初中生说的'），以及给学生发言做语言复杂度的自动检测。**在此之前我们不声称它已经足够真实。**"

### Q4 ⚠️ AI 学生的行为是不是你们自己写出来的？

- **评委为什么问**：**这是最尖锐的一问。** 潜台词是："如果都是你设计的，那测出来的结果有什么意义？"
- **推荐回答思路**：**不要否认，要承认并解释为什么这是必要的。**
  1. **承认**："学生行为有一部分确实是我们**参数化设定**的——参与度、原型、迷思概念都是我指定的。"
  2. **解释为什么必须这样**："因为**如果学生行为完全随机，评价就不可复现**。同一个师范生讲两次，可能因为学生随机性太大而得到完全不同的结果，那两轮对比就失去意义。**师范生训练需要的是'稳定的难度'，不是'随机的意外'。**"
  3. **划清边界**："但我们设定的是**参数与倾向**，不是**台词**。学生具体说什么、怎么表达困惑，是 LLM 在参数约束下生成的。而且——**SIR 这类指标确实会受我们参数影响，所以我们不把它作为教师能力的证据**（见 Q7）。"
  4. **加分点**："**关键事件（走神、沉默）由代码触发**，这是刻意的——为了 Demo 可复现、也为了评价公平。"
- **不应该说什么**：
  - ❌ "不是我们写的，是 AI 自己生成的"（一旦被追问细节就露馅）
  - ❌ "AI 学生完全自主"（不诚实，且逻辑上站不住）
- **继续追问怎么办**："那你们测的东西不就等于自己出题自己考？"
  → 回答："出题的是我们，**答题的是师范生**，判卷依据是**学界通行的 FIAS 标准**而不是我们自定的。就像考试：试卷是老师出的，但学生的分数仍然有意义——关键在于**评分标准是不是公开、稳定、可复核的**。我们的标准是公开的、指标是代码算的、结论是带证据的。"

> 📌 **这道题答好，印象分会大幅提升**——因为它显示你懂"实验控制"这件事。

### Q5 FIAS 为什么适合这个项目？

- **评委为什么问**：怀疑"FIAS 是不是硬套上去的"。
- **推荐回答思路**：
  1. FIAS 是**教育学界用了数十年的课堂话语分析工具**，有明确的九类定义，不是我们自创的；
  2. **它有现成的专家/新手基线可对照**——这就是为什么我们的报告能画出"专家人类教师 IDR=1.473，AI 教师 0.058"这条刻度线。**有基线的指标才是可解释的指标**；
  3. 它的原始形态就是**人工听课记录并编码**，天然适合"把重复劳动自动化"——**LLM 恰好擅长"单句分类"这件事**；
  4. **师范生训练关注的正是"教师话语结构"（是引导还是灌输）**，而 FIAS 恰好就是测这个的。
- **不应该说什么**：❌ "FIAS 是最先进的方法"（它不是"先进"，它是"经典且被接受"）
- **继续追问怎么办**："FIAS 是几十年前的方法，是不是过时了？"
  → 回答："**它是被广泛接受的测量工具，而不是需要追赶的技术。** 就像体温计发明很久了但医院还在用。而且我们的创新不在 FIAS 本身，在**把它从人工流程变成可自动运行的服务**——据我们查证，公开的相关研究里使用了 FIAS，但**其开源代码中没有任何 FIAS 编码实现，只有一张流程图**。"

### Q6 FIAS 自动编码准确吗？

- **评委为什么问**：直接打技术可信度。
- **推荐回答思路**：
  1. **先讲机制**：LLM 只做"**单句分类**"（第 42 秒这句话属于第几类），不做通读总结；类别必须是 1~9，否则重试；易混边界写成硬规则（举例："大家记住，考试要考" → 第 **6** 类指令，不是第 5 类讲授）。
  2. **再讲指标为什么一定准**：**指标由代码从编码结果统计**，不经过 LLM，所以**同一份对话重复计算的结果完全一致**。
  3. **最后讲验证方式**：随机抽 20~30 条，请学科教师**在不看 AI 结果的前提下**独立标注，比对一致率。
  4. **诚实说明进度**：一致率验证**尚未开展**（需要人力和学科教师配合），方案已就绪。
- **不应该说什么**：❌ "准确率 99%"（没有依据的数字是自杀）
- **继续追问怎么办**："如果分类错了，结论不就错了？"
  → 回答："会。所以有三层缓冲：**第一**，用规则卡把最容易混的边界写死；**第二**，指标层面做统计而不是依赖单句——错一两条通常不会改变 IDR 的量级判断；**第三**，报告里标注'编码为 AI 辅助'，并保留人工复核环节。**我们不会声称它是 100% 准确的。**"

### Q7 ⚠️⚠️ SIR 为什么可以证明教学效果？（**这是陷阱题**）

- **评委为什么问**：**这是专业评委会用来"验货"的一题。** 如果学生团队答"SIR 越高说明老师越会引导学生"，说明他们并不理解 FIAS。
- **推荐回答思路**：**必须直接纠正前提，而不是顺着回答。**
  1. **明确说不**："**SIR 不能用来证明教师的教学能力，我们也不这样用。**"
  2. **解释原因**："SIR 是'学生主动发起比例'。**在我们的系统里，'学生'是 AI，它的主动发言比例基本上是我们设定的参与度参数决定的**——我把参与度从 0.3 调到 0.8，SIR 立刻就上去了。**它测的是我的设置，不是师范生的能力。**"
  3. **给出正解**："所以我们只用**教师纯行为指标**做成效证据：**IDR**、等待时间、抢答率、提问层次、叫答覆盖度。其中 **IDR 最干净**——它在教师自己的话语内部分子分母（第 1~4 类 ÷ 第 5~7 类），**与学生说了多少话完全无关**。"
  4. **顺带展示我们读懂了文献**："论文里 AI 课堂的 SIR 高达 0.896，远超专家教师的 0.121——**那不是因为 AI 的学生更主动，而是因为那些发言是设计出来的。**"
- **不应该说什么**：
  - ❌ "SIR 提升说明学生更主动，所以教学更好"
  - ❌ 含糊其辞："这个指标我们也还在研究"（错过了展示严谨性的机会）
- **继续追问怎么办**："那你为什么还要报告这个指标？"
  → 回答："因为它仍然有描述价值——比如'这节节课教师话语占比 78%，学生发言集中在两位同学身上'，可以用来**描述课堂情境**。但我们在报告里把它和成效指标**分组呈现**，明确标注哪些用于判断改进、哪些只用于描述。"

> 📌 **这题如果答对了，是全场最能建立专业信任的一刻。请务必背熟。**

### Q8 如果 SIR 受 AI 学生参数影响怎么办？

- **评委为什么问**：Q7 的延伸，看有没有解决方案而不只是回避。
- **推荐回答思路**：
  1. **实验控制**：两轮试讲**使用相同的学生原型与参与度配置**（同一位学生、同一个知识点的迷思概念组合），确保两轮可比；
  2. **指标隔离**：把受参数影响的指标（TT/ST/SIR）与教师行为指标分离呈现；
  3. **敏感性检查（下一步）**：可以做一个小实验，固定教学内容、只改参与度参数，观察哪些指标会随之变化，**从而实证地证明"哪些指标不能用"**。
- **不应该说什么**：❌ "我们没考虑过这个问题"
- **继续追问怎么办**："那如果学生的表现影响了教师的发挥呢？"
  → 回答："这正是为什么两轮要用**同一套学生配置**。我们控制的是'难度'，让师范生面对的是**可比的挑战**，而不是'这次运气好、学生都配合'。"

### Q9 你们怎么证明教师真的进步了？

- **评委为什么问**：这是"成效"的核心问题，对应评分里的"应用成效"。
- **推荐回答思路**：
  1. **指标层面**：同一份教案两轮试讲，比较**教师纯行为指标**的变化（IDR、平均等待时间、抢答率、记忆型提问占比、叫答覆盖度、被忽略学生数）；
  2. **基线层面**：把两轮的 IDR 画在"专家教师 1.473 / 新手教师 0.885 / AI 教师 0.058"三条参照线上——**不只能说"变好了"，还能说"离专家还有多远"**；
  3. **可信度层面**：AI 编码与教师人工编码的一致性；
  4. **诚实边界**：行为指标改善 ≠ 教学能力永久提升。**我们不宣称后者。**
- **不应该说什么**：
  - ❌ "用户满意度 95%，所以教学能力提升了"（满意度不等于能力）
  - ❌ "我们的 IDR 提升了 4 倍，说明教学水平提升了 4 倍"（指标倍数 ≠ 能力倍数）
- **继续追问怎么办**："两轮就能提升？是不是太短了？"
  → 回答："**问得好，而且我们完全同意两轮不足以形成稳定能力。** 公开研究显示，模拟学生训练对'讲解表现'的效应很强（效应量约 0.90），但对'教学自我效能感'的提升很弱（约 0.20，作者自述一学期内不具定论性）。**所以我们的价值主张不是'练两次就变优秀'，而是'把每一次试错的成本降到接近零'**——它替代的是"没机会练"，不是"长期成长"。"

> 📌 **这个回答是本项目最成熟的一段话。它显示我们读过文献、知道边界、没有夸大。**

### Q10 有没有真实用户测试？

- **评委为什么问**：判断"是不是只有 PPT"。
- **推荐回答思路**：**诚实第一。**
  1. **当前状态**：**尚未开展。** 测试方案（被试招募、流程、指标、编码一致性校验、知情同意书）已就绪；
  2. **计划规模**：n≥10、目标 20 名师范生，每人完成两轮试讲（约 90 分钟）；
  3. **会产出什么**：四张图表（前后对比、IDR 基线对照、编码一致性、效能感子维度）；
  4. **如果已经在做**：直接报数字（这是最好的回答）。
- **不应该说什么**：
  - ❌ 编造数据（**最严重的错误，涉及学术诚信，且很容易被追问细节戳穿**）
  - ❌ "我们访谈了几位同学，反馈很好"（质性小样本不能当成效证据）
- **继续追问怎么办**："那你们现在凭什么说这个有用？"
  → 回答："**目前的依据是设计层面的论证，不是实证结果。** 我们的依据是：① 痛点有公开资料支撑（师范院校的公开报道明确提到'互评困境'）；② 机制有文献支撑（模拟学生训练对讲解表现有强效应）；③ 评价工具是学界既有标准（FIAS 有专家/新手基线）。**实证验证是我们下一阶段的第一优先级。**"

### Q11 数据从哪里来？

- **评委为什么问**：担心数据合法性。
- **推荐回答思路**：分三类说清楚：
  1. **教案**：师范生**自己上传**（自己的教学设计，产权清晰）；
  2. **试讲对话记录**：**系统运行时产生**，属于师范生本人；
  3. **迷思概念库**：依据**课程标准与学科教学知识整理**（公开的教育专业知识，非他人私有数据）；
  4. **明确声明**：**不使用任何真实学生数据、不采集影像音频、不涉及未成年人数据。**
- **不应该说什么**：❌ "数据是从网上抓的"（立刻引发合规问题）
- **继续追问怎么办**："迷思概念库是不是从别人的论文里抄的？"
  → 回答："我们整理的是**学科教学中公认的典型错误理解**，属于教育专业知识。**作为对照参考，我们查阅过开源项目的学科迷思概念文档（MIT 许可），并会在说明书中声明参考来源。** 我们不会直接复制受版权保护的内容。"

### Q12 迷思概念库从哪里来？可靠吗？

- **评委为什么问**：这是系统的地基，地基假则全盘假。
- **推荐回答思路**：
  1. **来源**：依据《义务教育数学课程标准》与学科教学知识整理，聚焦"负负得正"等典型难点；
  2. **目前规模**：20 条初中数学迷思概念初稿，其中"负负得正"细化出 6 种子迷思；
  3. **可靠性措施**：**必须由数学教育方向教师审阅后定稿**（当前状态：**尚未审阅**）；
  4. **诚实声明**：这是**教学经验归纳**，**不是**来自真实学生访谈的语料。如果能补上真实学生原话，可信度会显著提升。
- **不应该说什么**：❌ "这是我们从真实学生那里收集的"（如果没有，就是编造）
- **继续追问怎么办**："那你怎么知道这些错误真的会发生？"
  → 回答："**这些是学科教学中公认的典型错误类型**，一线教师普遍遇到过。但我们承认**它还没有经过系统性的实证校验**——这正是我们计划邀请数学教育方向教师审阅、并希望在后续版本中用真实课堂数据校验的原因。"

### Q13 换学科还能不能用？

- **评委为什么问**：测"可复制性"，直接对应"推广价值"。
- **推荐回答思路**：
  1. **架构上是可迁移的**：核心引擎（导演、学生运行时、编码、指标计算、闭环）**与学科无关**；
  2. **迁移时只需替换两个配置文件**：**迷思概念库** + **学段语言画像**；
  3. **但必须诚实**：新学科**需要重新做学科审阅**，不能宣称"开箱即用"；不同学科的可编码性也不同（如数学解题过程 vs 语文阅读讨论，话语结构差别很大）；
  4. **顺序**：先做通初中数学一个课时，再验证第二个课时，再考虑第二个学科。
- **不应该说什么**：❌ "所有学科都能用"（会被追问语文、体育、实验课怎么办）
- **继续追问怎么办**："那语文课怎么用 FIAS？"
  → 回答："**FIAS 本身是通用的课堂话语分析工具，语文学科同样适用。** 但'迷思概念'这个概念在数学和科学里最清晰，在语文学科里要换成'典型理解偏差'或'常见解读误区'——**这需要学科教师参与重新定义，我们现在不做这个承诺。**"

### Q14 为什么先做初中数学？

- **评委为什么问**：看选择是否有理由，还是随便挑的。
- **推荐回答思路**：四条理由：
  1. **迷思概念最清晰、最可枚举**（如"负负得正"的 6 种典型错误）；
  2. **对错相对客观**，评价争议小；
  3. **"负负得正"是公认的教学难点**——正因为它是"规定性知识"，学生极易退化为死记硬背，**恰好是诊断性教学的最佳训练素材**；
  4. **师范生基数大**（数学师范生数量多），推广面广。
- **不应该说什么**：❌ "因为数学简单"（不尊重学科，也不准确）
- **继续追问怎么办**："那你是不是只做了数学？"→ 回答："**是的，我们只做了数学的一个课时，这是有意的收敛。** 与其做五个学科都做不透，不如把一个课时的闭环做完整。"

### Q15 如果 AI 学生说错话、胡说、或者说不该说的话怎么办？

- **评委为什么问**：担心现场翻车或价值观风险。
- **推荐回答思路**：**分两类问题回答。**
  1. **技术层面的"胡说"**（扭曲事实、逻辑自相矛盾）：
     - 输出经 **Schema 校验 + 重试 + 降级**（格式错了就重试，重试仍失败则降级）；
     - 学生发言受**迷思概念库约束**（错误来自库，不是自由发挥）；
     - 发言受**语言约束**（句长、禁用词）；
  2. **内容安全层面**（不当言论、价值观问题）：
     - 系统提示词中设定角色边界与内容红线；
     - 使用**已备案的合规大模型服务**，不自行微调基础模型；
     - 保留**人工复核**环节（AI 报告需教师复核）。
- **不应该说什么**：❌ "不会发生这种情况"
- **继续追问怎么办**："万一演示的时候它胡说呢？"
  → 回答（**这段很实用**）："我们做了三重兜底：① **预跑数据可一键回放**——现场网络或模型异常时立刻切成已跑通的记录；② **完整录屏备份**；③ **降级路径**——模型超时时报告仍会完整输出，只是措辞朴素一些。**比赛演示不出错不是靠运气，是靠准备了两套方案。**"

### Q16 如果 AI 对教师的评价是错的怎么办？

- **评委为什么问**：评价错误在教育场景是高风险。
- **推荐回答思路**：
  1. **证据链**：每条结论必须挂原文证据，**教师可以自己看到"AI 是根据哪句话说的"**；
  2. **可申诉**：教师可对具体结论标记不同意，分歧记录保留；
  3. **不出具能力结论**：只描述行为 + 教育依据，不下"你能力不足"的判断；
  4. **人机协同**：AI 报告交指导教师复核，**最终解释权归教师**；
  5. **兜底**：明确说明报告为"AI 辅助分析"。
- **不应该说什么**：❌ "我们的 AI 不会错"
- **继续追问怎么办**："那 AI 判断错了，学生不就学错了？"
  → 回答："**这是我们把 AI 定位为'辅助'而不是'裁判'的原因。** 而且注意：**我们的评价不改教师的教案，也不改分数——教案修订必须由师范生逐条确认会不会改。** 系统只给建议，决定权始终在人手上。"

### Q17 会不会导致教师过度依赖 AI？

- **评委为什么问**：这是教育 AI 的经典伦理质疑（政策文件里明确提到"规避依赖成瘾"）。
- **推荐回答思路**：**这是我们的设计重点，有三条硬设计。**
  1. **反思不代写**：反思环节**没有"AI 帮我写"按钮**，这是刻意去掉的，AI 只追问；
  2. **教案修订逐条确认**：AI 只给建议（含理由），**必须由师范生逐条接受或拒绝**；
  3. **AI 报告交导师复核**：不让人只信 AI。
  4. **顺带引政策**：《关于加快推进教育数字化的意见》（二十二）明确要求"有效规避……算法霸权、依赖成瘾"，这是我们设计时就直接对标的条款。
- **不应该说什么**：❌ "AI 只是工具，不会有依赖问题"（空话）
- **继续追问怎么办**："你怎么证明学生用了系统之后没有变懒？"
  → 回答："**我们无法证明，也不打算声称。** 我们能做的是**在系统设计上不提供代写功能**，并在用户测试的访谈提纲里专门问一个问题：'你更希望 AI 直接帮你写吗？'——**如果多数人回答'希望'，那说明我们的设计在跟用户偏好对抗，是需要认真对待的信号。**"

### Q18 有没有隐私风险？

- **评委为什么问**：直接对应评分里"合规与伦理 15 分"，且是**一票否决性质**。
- **推荐回答思路**：主动、结构化地说，**把"没有采集"当成优势讲**。
  1. **最小采集**：只采集主动上传的教案与文本试讲记录；
  2. **⭐ 不采集影像、音频、人脸、眼神、行为轨迹**——**这是刻意放弃**。同类系统常用摄像头+麦克风分析眼神、语速、语调，我们不做。**理由是隐私成本与伦理成本过高，而我们不需要这些数据也能算出教学行为指标。**
  3. **涉未成年人数据**：不涉及（虚拟学生是合成角色，不采集真实学生数据）；
  4. **用户权利**：数据可查看、可删除；未经书面授权不用于展示；
  5. **知情同意**：测试前签署，访谈录音单独授权。
- **不应该说什么**：❌ "我们不存数据"（不真实，无法训练和对比）
- **继续追问怎么办**："你们存在哪里？会不会泄露？"
  → 诚实回答："**比赛阶段部署在本地/私有环境，数据不出本地。** 如果要正式推广，我们会做数据分类分级、访问控制与加密存储——**这部分目前还没做，是我们的待办。**"

### Q19 为什么这个项目需要 Agent？不用 Agent 行不行？

- **评委为什么问**：**这是"技术必要性"质疑。** 很多项目为了"显得先进"硬上 Agent。
- **推荐回答思路**：**承认不是所有地方都需要 Agent，然后说清哪里真的需要。**
  1. **真的需要 Agent 的地方**：
     - **多个 AI 学生**——每个学生是独立角色，有独立状态和人格，**这天然是多智能体问题**；
     - **导演**——需要有人决定"谁该说话"，这是独立的决策职责；
     - **编码 / 评价 / 反思 / 修订**——**输出契约与失败模式完全不同**，混在一个 prompt 里会互相污染（这是我们从源码级调研里得到的教训）。
  2. **不需要 Agent 的地方（我们确实没用 LLM）**：
     - 指标计算、统计、对比、事件触发、数据校验——**全部是纯代码**。
  3. **加分观点**："**多智能体不是为了显得先进，而是因为教育场景天然就是多角色、多职责的。** 但我们也刻意避免'为了多而多'——比如单 Agent 场景不需要 LLM 参与调度时，我们走纯代码。"
- **不应该说什么**：❌ "因为 Agent 是趋势"（会被立刻看轻）
- **继续追问怎么办**："九个 Agent 是不是过度设计了？"
  → 回答："**一期我们实际只做 6 个**（导演、教案分析、铸造工坊、虚拟学生、编码、评价），反思教练和教案修订师可以用更轻的方式先实现，学科教研员明确放到二期。**我们宁愿少做几个、做扎实。**"

### Q20 这个项目最大的技术难点是什么？

- **评委为什么问**：看有没有真的动过手（没做过的人会说"调 API"）。
- **推荐回答思路**：**给一个有说服力的、具体的技术难题，并展示你已经想清楚。**
  > "最大的难点不是'让 AI 说话'，而是**让学生'记住自己不懂'**。"
  1. **具体表现**：LLM 扮演学生时有一个很顽固的问题——**上一轮答错了，下一轮被追问就'变聪明'了，突然答对**。这会摧毁教学训练的价值：师范生正在练"怎么把一个错误理解纠正过来"，结果学生自己好了。
  2. **我们的解法**：给每个学生维护一个**认知状态机**（`understanding / confusion / emotion / convinced`），每轮发言后回写状态，下一轮的提示词里把这个状态注入进去，并明确要求"**你的理解程度由状态决定，不能因为老师讲了一遍就自动变懂；要变，必须由状态变化驱动**"。
  3. **为什么难**：这需要把"状态"和"生成"两件事拆开——状态由代码维护，生成受状态约束。**纯靠提示词是压不住的。**
- **不应该说什么**：❌ "难点是 API 调用/配置环境"
- **继续追问怎么办**："还有别的难点吗？"
  → 接着讲："第二是**行为可控性**——学生不能每轮都说话，也不能一直不说话。第三是**FIAS 编码的边界判定**，比如'大家记住，考试要考'到底算讲授还是指令。"

### Q21 你们的创新点别人做过吗？（诚实题）

- **评委为什么问**：**这是在测学术诚信和文献功底。** 答"没人做过"是危险的。
- **推荐回答思路**：**主动说出对方可能知道的先例，然后精确划出我们的位置。**
  1. **主动承认**：
     - "**让 AI 扮演带迷思概念的学生，已有先例**——有研究用聊天机器人扮演'比例推理有迷思概念的初中生'（发表于国际期刊）；也有做'教师创建模拟学生'的工具（面向教师，30 名教师参与过使用研究）。"
     - "**AI 评课在师范院校也已有成熟系统**，服务过上千名师范生，并做过与多位学科专家评分的一致性验证。"
  2. **精确划界**：
     - "但**把它做成'反事实学生 → FIAS 行为量化 → 反思 → 教案迭代 → 二次试讲对比'的完整训练闭环，我们没有查到公开工作**。"
     - "而且有一个具体的技术空缺：**FIAS 被广泛使用，但公开实现里没有自动编码代码**——这可能是我们最硬的一个点。"
  3. **价值主张收敛**："**我们不是发明了一个新机制，我们是把几个已被验证的机制第一次接成了闭环。**"
- **不应该说什么**：
  - ❌ "我们是全国第一个/首创"（极危险）
  - ❌ "这个方向没人做过"（一定有人做过一部分）
- **继续追问怎么办**："那你这不就是把别人的东西拼起来？"
  → 回答："**是整合创新，我们从不掩饰这一点。** 但请注意：① 整合的难点在**闭环的工程实现**（状态一致性、指标可审计、两轮可比）；② 我们补上了一个真实空缺（**FIAS 自动编码**）；③ 更重要的，**我们做了别人没做的收敛**——明确了哪些指标不能用（比如 SIR），这本身就是学术贡献。"

### Q22 你们用了开源项目，是不是抄的？

- **评委为什么问**：比赛要求"作品必须为原创成果，无任何知识产权争议"，这是**一票否决项**。
- **推荐回答思路**：**主动披露，越透明越安全。**
  1. **说清许可**：我们参考的项目是 **MIT / Apache-2.0** 许可，**允许商用与修改，只需保留版权与许可声明**；
  2. **说清参考了什么**：参考的是**架构设计层面**的东西（多智能体调度范式、可插拔环节状态机、结构化输出与降级策略、人在环反馈模式），**并在代码仓库与说明书中列明**；
  3. **说清什么是自研**：多学生行为控制、认知状态机、FIAS 自动编码、指标计算、建构一致性对齐矩阵、两轮闭环——**这些是我们的实现**；
  4. **说清方法论引用**：FIAS 九类与指标公式**引自公开论文**，论文仓库本身没有实现代码；我们引用的是**方法论**。
  5. **主动加一句**："**我们还刻意避开了一些有许可风险的组件**，比如某个 PDF 解析库是 AGPL 许可、某个数字人 SDK 商用需单独签约——我们选择替代方案或不做。"
- **不应该说什么**：
  - ❌ "我们完全是自己从零写的"（如果参考了却不承认，风险更大）
  - ❌ 含糊说"参考了一些开源项目"却举不出来（显得心虚）
- **继续追问怎么办**："具体哪个文件参考了哪个项目？"
  → 回答（**这块要提前整理成一张表**）："我们的说明书里有一张表，逐项列出了参考项目、其许可类型、我们参考的具体内容。**我们欢迎评委核查。**"

## 20 最终 Demo 应该长什么样

> 完整分镜见同目录 `07_展示视频分镜脚本.md`。这里只讲**必须做到什么**和**绝不能做成什么**。

### 20.1 Demo 的四个必备画面（缺一个就不合格）

| # | 画面 | 为什么必备 |
|---|---|---|
| 1 | **学生顶嘴且坚持错误** | 证明 AI 学生不是"配合型聊天机器人"——这是全片最能证明"我们有对抗性"的一刻 |
| 2 | **被忽略的学生被可视化**（"小周已被忽略 11 分钟"） | 教育价值最直观、最容易被评委记住；几乎无人做 |
| 3 | **报告里每条结论都能点回原文高亮** | 证明评价不是黑箱，回应"AI 评价可信吗"的质疑 |
| 4 | **两轮对比的数字变化**（IDR 0.12 → 0.58） | **证明闭环存在**。没有这一屏，项目就退化成"AI 评课工具" |

### 20.2 三个"绝不能"

| ❌ 绝不能做成 | 为什么 |
|---|---|
| ❌ 只有一个网页聊天框，用户说"我要试讲"，AI 回一大段评价 | **这样核心价值就完全没体现出来。** 评委的第一反应会是"这不就是 ChatGPT 套壳" |
| ❌ 只演示"AI 评价得多准" | 评价准不是壁垒（已有同类系统做过千人验证）。**壁垒在闭环** |
| ❌ 演示"分数很高/提升 4 倍"这类话 | 用满意度或指标倍数伪装能力提升，是评审最容易击穿的地方 |

### 20.3 正确的 Demo 定位

> **应该做成**：`AI 学生模拟 + 可控课堂行为 + FIAS 分析 + 教学诊断 + 二次试讲 + 前后对比`
> **核心体验**：让评委在 5 分钟内亲眼看到——**"这节课我讲砸了 → 系统告诉我砸在哪、凭什么这么说 → 我改了 → 再讲一次 → 数字变了"**。

### 20.4 Demo 的兜底（必须准备）

- [ ] 固定一份教案，**不现场随机**
- [ ] 全流程**预跑一遍并落库**，准备"一键载入历史会话"
- [ ] **完整录屏备份**（U 盘 + 本地双备份）
- [ ] 模型超时的**降级路径**（报告仍完整输出，只是措辞朴素）
- [ ] 彩排 **10 遍以上**（试讲那一镜最需要）

## 21 项目可行性分析

| 维度 | 评价 | 理由 |
|---|---|---|
| **1. 技术可行性** | 🟢 **高** | 所有技术都是成熟件：LLM 做角色扮演与单句分类、Python 算指标、数据库存事件流、前端画图。**没有一项需要自研算法**。最大技术风险是"AI 学生真实性调优"，但那是工作量问题，不是可行性问题 |
| **2. 教学可行性** | 🟢 **高** | 评价工具全部取自师范教育既有的成熟体系（FIAS、建构一致性、布鲁姆、等待时间），**不需要说服教师接受一套新评价观**；且与《微格教学》课程的标准训练循环完全一致，**天然可嵌入现有课程** |
| **3. 比赛展示可行性** | 🟡 **中高** | 有天然的记忆点（学生顶嘴、被忽略的学生、两轮对比）。**但有一个真实风险**：如果界面主要是一个对话流，容易被误判为"聊天机器人"。**必须靠常驻的"座位区 + 实时标签瀑布 + 被忽略计时器"来制造差异感** |
| **4. 用户需求** | 🟢 **高** | 痛点有公开资料支撑（师范院校公开报道明确提到"互评困境"、评价流于表面）；且已有同类系统服务上千人，**说明需求真实存在而非我们臆想** |
| **5. 创新性** | 🟡 **中等偏上** | 三个零件（虚拟学生、AI 评课、自动改教案）单独都不新；**新的只有"装配方式"**——反事实学生 + FIAS 自动编码 + 建构一致性对齐 + 两轮闭环。**创新性完全取决于表述是否克制、机制是否真的做通** |
| **6. 实现难度** | 🟡 **中等（但 3 人上限下偏紧）** | 名义工作量 **3 人 × 8 周**（已按"团队 ≤3 人"折算）。**难点不在编码，而在三件事**：AI 学生的行为可控性、认知状态一致性、编码可信度验证。**3 人必须砍范围**（削减清单见 `03` 的 H.5） |
| **7. 最大风险** | 🔴 **两个** | ① **样本与成效**：n≥10 的两轮用户测试需要时间与人力，而"应用成效"占 15 分——**测试做不完，材料就空**；② **表述过度**：把"整合创新"说成"首创"，会在答辩时被击穿（见第 12 节诚实边界、第 16 节 Q21） |

### 21.1 综合判断

> **这是一个"技术上不难、但判断上很容易做错"的项目。**
> 技术不会挡住你；**挡住你的是"有没有人肯去做那三件枯燥但决定成败的事"**——可信的评价语料、像学生的教学内容、完整的用户测试。
> **可行性总体：可以做成，而且有机会拿奖**，前提是**收敛功能、做实闭环、说清边界**。

### 21.2 ⚠️ 这个项目最不能做成什么样

> **如果最后只是一个网页聊天框：用户输入"我要试讲"，AI 回复一大段评价，那么项目的核心价值就没有体现出来。**
>
> 真正应该做成的形态是：
> **AI 学生模拟 + 可控课堂行为 + FIAS 分析 + 教学诊断 + 二次试讲 + 前后对比。**
> **这才是项目的核心。少任何一环，项目就会退化成一个普通的教育聊天机器人。**
